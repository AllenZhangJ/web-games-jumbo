# ADR-094：局外研究页必须把单一下一目标做成可切换验证面

## 状态

已接受（2026-07-28）

## 背景

Arena 的长期内容深度来自武器收集、武器地面/空中熟悉、地图段落熟悉和生存记录。无渲染原型已经把这四类进度收敛成一个 `resolveArenaV2UiNextGoal()` 结果，但独立 11 页面研究页此前只展示页面合同和关键流程，没有把结算后的下一目标呈现给研究者和参与者。

如果不把目标合同放进同一研究面，无法检查四个阶段是否始终只给一个行动，也容易在真实页面接入时重新膨胀成任务列表或复杂养成入口。

## 决策

在 `ui-information.html` 研究页增加“结算后的单一下一目标”工作区：

1. 直接消费 `resolveArenaV2UiNextGoal()`，不在 DOM 层复制目标排序或进度判断；
2. 提供收集、熟悉、地图、生存四个固定研究阶段，用于检查目标排序、理由、进度和立即行动；
3. 每个阶段只渲染一个目标标题、一个理由、一个进度条和一个立即行动，不增加任务列表、奖励树或持久化状态；
4. 研究页继续保持 `noindex`、不进入生产构建，并保留 48px 最小触控目标。

## 影响

- 正向：单一下一目标从纯函数合同变成可切换、可观察的研究界面；
- 正向：能够在真机/真人测试前发现目标文案、进度比例和操作入口是否清晰；
- 边界：这只证明研究页渲染与合同一致，不证明生产结算页、持久化数据或留存指标已经完成；
- 边界：四个阶段是研究夹具，不是正式玩家进度。

## 验证

- 页面合同 Web 边界测试检查目标导航、目标预览和 resolver 接入；
- `ui-information.html` 继续不进入生产构建；
- 后续仍需真实手机触控、真人阅读率和结算后再次开始率证据。
