# ADR-055：武器上下文必须完整显示关键数值

- 状态：已接受，适用于当前主页武器卡与 V2 研究展示边界
- 日期：2026-07-27
- 范围：`ProductContentPresentationDefinition.overview.contexts` 的数值投影与 Web 展示

## 背景

热血英豪式武器的差异不只在“这把武器是什么”，还在同一把武器处于地面、空中或不同高度关系时，攻击距离、前摇、击退、垂直控制和可命中的高度范围如何变化。当前 Arena 已经把这些值从权威动作调优投影到地面/空中上下文，但 Web 卡片只显示距离、前摇和横向作用，垂直控制没有出现在可见文本中；上下文数值也只有悬浮标题，没有标签，玩家难以知道每个数字代表什么。

这会把“动作上下文”退化成一句描述，无法支持玩家学习武器，也无法证明空中动作确实与地面动作不同。

## 决策

每个武器上下文至少公开以下八项数值，且全部来自对应的权威动作调优：

1. 有效距离 `range`；
2. 覆盖宽度 `coverage`，由 targeting 的胶囊半径或正面方向角推导；
3. 出招时间 `startup`；
4. 有效攻击窗口 `active-span`；
5. 横向击飞距离 `impact`；
6. 垂直控制冲量 `vertical`；
7. 方向容错角 `direction-tolerance`，表示攻击方向允许偏离目标的几何范围；
8. 命中高度差 `height-gap`，表示目标与攻击者允许存在的最大垂直差。

Web 卡片必须把每项数值以“标签 + 方向语义 + 原始值 + 单位”显示，并同步提供 `title` 与 `aria-label`。上下文区域允许换行，不以截断或只显示无标签数字换取单屏密度。

主比较矩阵仍只显示统一的 9 个核心字段；上下文八项用于理解地面/空中动作差异，不在不同上下文之间伪造一个不具备共同语义的总评分。有效窗口和方向容错同时进入独立的行为数值比较行。

## 被考虑的替代方案

### 继续只显示三个数字

- 优点：卡片更紧凑；
- 放弃原因：垂直控制和高度差是空中动作的核心差异，隐藏后无法解释下砸、浮空和高低差命中。

### 只在悬浮提示里补充字段

- 优点：不改变视觉布局；
- 放弃原因：移动端和触摸设备没有稳定悬浮状态，辅助技术也无法把无标签数字解释成动作语义。

### 为每把武器做一套自定义数值

- 优点：可以只展示设计者认为重要的字段；
- 放弃原因：会让武器之间失去可比较的公共语言，也会让新增武器再次回到手写 UI 数值的漂移风险。

## 后果

正面影响：

- 玩家可以直接比较同一把武器的地面/空中命中边界；
- 数值展示与热血英豪研究中的“空间上下文”保持一致；
- 规则、表现内容、ViewModel 和 DOM 之间的数值链路仍然只有一个权威来源；
- 后续加入投射、延迟区域或垂直击飞武器时，可以复用同一组上下文数值合同。

限制：

- 完整显示关键数值不等于玩家已经理解武器，还需要真人解释率和真机阅读验证；
- `height-gap` 表示命中判定范围，不表示实际击飞高度，实际结果仍由冲量、物理和地图共同决定；
- `coverage` 表示几何影响宽度，不等于实际命中率，实际结果仍由方向、移动、前摇和地图共同决定；
- `direction-tolerance` 表示几何方向范围，不等于真实命中率，目标朝向、移动和遮挡仍会改变结果；
- 当前只有三把 Arena 武器接入该展示，更多功能族仍需先通过研究原型验证。
