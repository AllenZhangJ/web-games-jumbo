# ADR-064：武器必须先通过最小功能版本合同

- 状态：已接受，已接入开发/测试工具链
- 日期：2026-07-27
- 范围：V2 武器研究卡、战斗语言评审和后续武器 Definition 提案

## 背景

热血英豪的武器差异来自基础输入在距离、方向、时机、资源和地形中的不同结果。Arena 不复制其复杂连招、职业特效、格挡、自动锁定或多套资源，但仍需要保留每把武器的核心问题。

当前研究卡已经记录 12 件参考武器，参考武器归并为 7 类；但当前生产重锤已经使用“推离”语义，却没有对应的显式语言合同。公开数值轴也已经有就绪检查。剩余风险是：`arenaMinimumVersion` 还是一段文本，无法自动确认一把武器是否同时声明了最小输入、地面/空中上下文、命中结果、地图关系、失败成本、反制和不复制项。

## 决策

1. 为 8 种战斗语言各声明一份结构化最小版本规格：7 种来自参考武器研究，另加生产基线的“推离”；所有规格只使用一个 `primary-attack` 输入，并固定声明 `ground` 与 `aerial` 两个上下文。
2. 每份规格必须写清命中条件、时机、命中结果、地图关系和失败成本；反制与不复制项不得只存在于自由文本研究笔记。
3. 12 件参考卡通过功能族映射投影到参考语言规格；当前生产 `hammer / chain / shield` 通过显式生产映射投影到 `推离 / 换位 / 冲入`。每个投影结果必须可确定性重建、不可变，并绑定公开数值轴就绪报告。
4. `ready` 仍只表示公开轴可解释；封路、延迟重击等依赖 `delay`/`warning` 的语言继续保持 `blocked`，不得因为合同存在而进入生产武器。
5. 合同只属于开发/测试工具链，不直接创建生产装备。进入生产前仍需独立的 Definition、规则/回放、地图后果、真机和真人证据。

## 被考虑的替代方案

### 继续使用 `arenaMinimumVersion` 文本

- 优点：修改最少。
- 放弃原因：无法检查最小版本是否有反制、失败成本和地图关系，也无法阻止“描述很完整但动作不可读”的候选进入评审。

### 每件参考武器都直接创建一份生产 Definition

- 优点：研究到代码的距离短。
- 放弃原因：会把参考游戏的复杂度和未验证数值直接带入生产，并绕过战斗语言和公开轴门禁。

### 只按语言保留一份文本，不投影研究卡和生产武器

- 优点：合同更短。
- 放弃原因：会丢失官方案例的来源、地图用途和不复制边界，无法回答每件参考武器如何被抽象。

## 后果

正面影响：

- 新武器先回答“最基础的乐趣是什么”，再讨论资产和复杂效果；
- 研究卡、公开数值和后续 Definition 有稳定的中间边界；
- 评审可以区分“核心语法未成立”“数值轴未公开”和“真人/地图尚未验证”。

限制：

- 当前合同仍不能证明真人 3 分钟掌握或 200 小时留存；
- 8 种语言不等于首发 8 把武器，首发数量和正式数值仍需平衡与体验评审；
- 封路、延迟重击、真实多人拥挤和 V2 权威迁移仍未完成。
