# ADR-077：研究武器概览必须分离地面与空中上下文

- 状态：accepted
- 日期：2026-07-28
- 范围：Arena V2 研究武器概览矩阵、候选 Definition 数值投影与后续 UI 消费

## 背景

候选武器已经拥有独立的地面/空中 `ActionDefinition` 和数值投影，但原研究比较矩阵只把地面数值放入 `stats`，导致代码证据弱于文档承诺。这样玩家无法在同一张武器卡里判断“这把武器空中更远还是地面更稳”，也容易把空中动作误读成地面动作的换皮。

## 决策

1. `ArenaV2WeaponResearchOverviewRow` 使用 `contexts` 作为唯一上下文入口，固定包含 `ground` 与 `aerial` 两个上下文；每个上下文独立携带 9 项主数值和 2 项行为数值。
2. 每个上下文的数值都由对应的候选 `ActionDefinition` 投影生成；研究矩阵不复制 UI 手写值，也不把地面/空中合成为一个总评分。
3. 同一上下文内的 `maxValue` 使用同一批候选的相同来源字段计算，保证横向条形比较可解释；地面和空中分别比较，避免不同动作语义被强行放在同一尺度。
4. 核心动词、命中结果、地图用途和反制仍是武器行级信息；数值上下文只回答“在这个状态下能做到多少”，不替代玩家可读的语义文案。
5. 该结构目前属于研究/候选展示层，不改变默认生产武器目录；进入正式生产前仍需通过真人解释率、目标设备可读性和生产迁移门禁。

## 被拒绝的替代方案

### 继续只显示地面数值

拒绝原因：会让具有明显空中差异的武器在概览中失去主要学习点，和热血英豪中地面/跑动/空中动作形成不同空间答案的证据不一致。

### 把地面与空中数值拼成一组平均值

拒绝原因：平均值无法告诉玩家什么时候使用哪套动作，且会掩盖一个上下文强、另一个上下文弱的真实差异。

### 用每把武器自定义字段替代公共轴

拒绝原因：会重新引入不可比较的卡片和 UI 漂移；公共轴必须保持稳定，差异由上下文值、命中结果和地图用途体现。

## 后果

- 研究矩阵与正式产品已有的 `overview.contexts` 结构一致，后续 UI 可以直接消费；
- 数据量增加，但玩家能直接比较地面/空中距离、覆盖、前摇、击退和方向容错；
- 仍然不能据此证明真人一定看懂，必须继续做 10 秒数值解释、地面/空中复述和设备可读性任务；
- 生产武器和默认入口不受本研究 API 变化影响。
