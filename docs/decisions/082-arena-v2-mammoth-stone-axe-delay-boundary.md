# ADR-082：延迟落点先以预警区和整数 tick 验证

- 状态：已接受，已接入开发/测试工具链原型
- 日期：2026-07-28
- 范围：猛犸石斧式延迟落点、预警、路线/高度反制，不进入生产武器 Definition

## 背景

猛犸石斧的研究价值不是单纯的重击，而是“动作已经开始，但命中还没有发生”。玩家需要在预警期间判断继续站位、改变路线或改变高度。当前 Arena 的 ActionDefinition 还没有把预警和延迟落点作为独立字段，直接把官方约 3 秒写成正式数值会把外部游戏的时间语义误认为 Arena 的平衡合同。

## 决策

1. 先用已有整数 tick 预警区验证四类可观察结果：站在原处被命中、提前改变路线、落点 tick 改变路线、提前改变高度。
2. 命中判定在有效 tick 读取目标位置；不在动作开始时锁死目标位置。
3. 预警 tick、有效窗口、覆盖半径和高度容错分开记录，并为命中、路线躲避和高度躲避提供不同反馈因果。
4. 原型使用 `research-hypothesis` 标记的固定对照值，不迁移官方秒数、猛犸公共危险、自伤、恢复物、三次恢复或原作资源系统。
5. 在没有正式 Definition 字段、Replay 事件、表现反馈和真人/设备证据之前，猛犸石斧保持研究工具链状态。

## 被考虑的替代方案

### 直接将延迟写成现有 windup

- 放弃原因：现有字段不能区分“玩家看见预警的阶段”和“命中有效窗口”，也无法稳定表达落点 tick 的路线反制。

### 在表现层显示倒计时并自行判定命中

- 放弃原因：会让表现层参与规则判定，破坏 Rule → Core → Presentation 依赖方向和 Replay 确定性。

### 复制官方约 3 秒、猛犸、自伤和恢复物

- 放弃原因：这些是原作的完整系统组合，不是本项目已经验证的最小功能版本，会扩大规则、反馈和成长复杂度。

## 后果

正面影响：

- 可以先验证延迟武器最重要的“看见—回应—命中/躲避”闭环；
- 路线躲避与高度躲避有独立因果反馈，便于后续做命中与反馈评审；
- 研究数值不会伪装成生产平衡，也不会写入存档或匹配合同。

限制：

- 当前探针不是正式 MatchCore 动作，不证明滚动物体、墙面反弹或多人公共危险已经成立；
- 固定 tick 只是对照，尚未证明玩家能在真实画面和声音中及时理解预警；
- 若要生产化，必须新增权威 telegraph/delay 合同，并重新通过确定性、Replay、反馈、设备和真人门禁。
