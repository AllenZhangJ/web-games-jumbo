# ADR-101：弹壳特攻队参考只转译为统一局外布局节奏

- 状态：Accepted
- 日期：2026-07-28
- 范围：Arena V2 战斗外 11 页面研究工具链

## 背景

现有 11 页面合同已经明确了玩家问题、首屏最多三项信息、点击预算和单一下一目标，但原型主要以信息列表呈现，不能直接观察页面的视觉层级。这样容易出现“合同很清楚，页面仍然把所有内容摊平”的问题。

官方《弹壳特攻队》页面把核心体验压缩为单手操作、海量敌人、Roguelike 组合和多变难度；官方生存指南又用自动追击/面对方向和开阔空间/首领场景解释行为差异。[官方 App Store 页面](https://apps.apple.com/cn/app/%E5%BC%B9%E5%A3%B3%E7%89%B9%E6%94%BB%E9%98%9F/id1628270358)、[官方生存指南](https://apps.apple.com/cn/ipad/story/id1649510203)这些资料支持“先让玩家知道当前目标和行为差异”的信息方向，但不能证明 Arena 应复制其具体截图或系统。

## 决策

在现有 `ui-information.html` 研究页中，为每个 11 页面合同增加统一布局草图：

1. 顶部保留页面身份和研究标记；
2. 中央英雄区只表达“当前决定/下一步”与页面问题；
3. 首屏信息最多生成三张语义卡，卡片直接来自 `firstViewInformation`；
4. 只保留一个视觉主动作，直接来自 `primaryAction`；
5. 底部只展示开始、武器、地图、记录四类信息入口的导航暗示；
6. 详情、个人记录、地图适配等 `deferredInformation` 继续放在草图下方，不挤进英雄区；
7. 研究页保持 `noindex`、不进入生产构建，也不引入商城、宠物、科技、活动、多货币或新的页面 ID。

## 选择的原因

- 让“页面合同”直接变成可观察的层级，而不是另写一套静态截图说明；
- 用一个主动作和三张信息卡承接参考对象的“快速开始 + 重点选择”节奏，同时保持 Arena 的武器/地图核心；
- 所有文本仍由唯一页面合同生成，避免研究页出现第二套页面真相；
- 视觉草图可以在真实窄屏中检查卡片堆叠、按钮宽度和页面滚动，而不需要把未完成的生产状态机接入。

## 放弃的方案

### 直接复制参考对象截图

无法证明素材授权，也会把参考对象的复杂成长和运营结构一并带入；本项目只学习信息节奏和行为化表达。

### 每个页面独立设计一套布局

会让 11 个入口变成 11 种操作语言，增加学习成本，也违背“简单入手、清晰明了”的目标。

### 继续只展示信息列表

合同可测试，但无法验证目标、信息卡和主动作是否形成真正的视觉优先级。

## 后果

- 11 个页面现在都有统一的“目标 → 三项信息 → 一个主动作 → 四类入口”可视化骨架；
- 布局草图证明信息层级和窄屏布局，不证明真实手机字号、触控命中率、真人阅读率或留存提升；
- 后续生产页面如果偏离该骨架，必须说明是哪一个页面问题需要例外，而不能仅以“参考对象有这个功能”为理由扩展；
- 下一步真人测试应记录玩家是否能在 5 秒找到主动作、10 秒说出武器差异，以及结算后是否愿意再次开始。
