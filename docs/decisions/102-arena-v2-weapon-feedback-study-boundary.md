# ADR-102：命中反馈先用真实因果探针做独立阅读研究

## Status

Accepted（研究工具链）

## Date

2026-07-28

## Context

Arena 的武器价值不仅由“是否命中”决定，还由命中后是否仍有支撑面、是否转移到另一处落点，以及玩家是否在命中前自己掉落决定。当前 Rule/Physics 已经输出五种因果反馈，`WeaponFeedbackPresented` 也已经把它们映射为视觉、音频和强调 Cue；但事件链和 Three 灰盒仍不足以回答一个产品问题：玩家看到反馈后，能否说出下一次该调整武器、路线还是回应？

如果把五种结果压成一个通用命中特效，玩家会把武器差异、地图后果和路线失误混为一谈；如果直接绑定最终资产，又会把未经真机和真人验证的声音/特效当成产品结论。

## Decision

新增独立研究页 `feedback.html`，只消费现有真实 KZ 规则探针和 `projectArenaV2WeaponFeedbackPresentationEvent`，形成五个可交互判断任务：

1. 命中确认：位置改变但保留当前支撑面；
2. 支撑面转移：命中后落到另一处支撑面；
3. 击落：命中后失去支撑面；
4. 攻击被避开：有效窗口前离开攻击线；
5. 路线失误：玩家先于命中失去支撑面。

页面先展示武器、路线段、回应动作以及视觉/音频 Cue，不展示权威答案；提交后再展开真实 Replay/Physics 结果、反馈标题和解释。研究页使用 90 个 KZ 探针中的每类首个确定性代表样本，不能进入生产入口，也不能把研究页答题结果当作真人解释率。

## Alternatives Considered

### 直接在生产主页增加五种提示

- 优点：玩家马上能看到差异。
- 拒绝：当前最终声音/特效、真机密度和真人解释率尚未验收；生产入口应继续只消费已批准的表现合同。

### 只做事件单元测试

- 优点：实现成本低，能证明字段和 Cue 不漂移。
- 拒绝：单元测试不能观察玩家是否能从视觉/音频信号建立因果解释。

### 复用武器数值可读性页

- 优点：减少页面数量。
- 拒绝：数值解释和命中反馈是两个不同认知任务；合并会让“比较数值”和“解释一次失败”互相干扰。

## Consequences

- 研究任务现在可以逐类收集命中、落点转移、击落、闪避和路线失误的判断结果，并导出 JSON。
- 反馈事件仍由权威结果产生，研究页和 Presentation 都不能重新推断命中原因。
- 研究页只验证 Cue 与因果说明的可观察关系，不验证最终资产质量、触控设备表现、多人同步或留存。
- 只有完成真机、真人、多人和最终声音/特效验收后，候选武器才可重新评估生产迁移门禁。
