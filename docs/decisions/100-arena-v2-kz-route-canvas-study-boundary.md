# ADR-100：KZ 路线先用真实画布验证路线职责，再进入地图制作

- 状态：Accepted
- 日期：2026-07-28
- 范围：Arena V2 KZ/竞速/生存共用地图研究工具链

## 背景

当前 KZ 研究已经有六段路线合同、四条分叉路线、轻量物理灰盒、相机几何观察和武器攻击点探针，但这些证据主要来自无渲染函数和数据表。它们能证明规则关系，却不能让设计者直接观察“主路线、快线、恢复线、终点和攻击点是否在同一张图里可读”。

外部 KZ 资料把路线能力拆成 longjump、bunny hop、strafing、连续段落、检查点和难度标签；[KZ-Rush 难度标准](https://kz-rush.com/en/article/map-difficulty-criterias)、[CS1.6 KZ 入门资料](https://steamcommunity.com/sharedfiles/filedetails/?id=3272385460)和[社区地图目录](https://steamcommunity.com/app/626680/workshop/)都说明了“按移动问题分段”和“记录完成/熟练”的价值。

## 决策

新增独立研究页 `kz-map-study.html`，以真实 Canvas 画布消费已有研究合同：

1. 画布显示六段主路线、四条研究分叉、起点和竞速终点；
2. “竞速/生存”切换只改变终点和段落职责，不复制第二套地图几何；
3. “快线/恢复线”切换只选择已有分叉合同，不把路线选择扩展为新操作；
4. 点击段落或画布区域，显示六维难度、已有回应、恢复关系和生存职责；
5. 攻击点按入口、转折、出口循环标记，并在有分叉探针时显示命中/击落/落点转移摘要；
6. 来源卡同时展示外部事实、Arena 迁移结论和“不复制”边界；
7. 页面只存在于开发/测试工具链，不能进入生产 `index.html`、小游戏入口或正式地图资产。

## 选择的原因

- 画布验证“路线关系是否能被看见”，函数原型验证“规则关系是否能被计算”，两者职责不同；
- 研究者可以在一页内观察竞速和生存复用、分叉风险和攻击点，而不需要把研究结论翻译成口头描述；
- 只消费既有 `JumpRoutePrototype`、KZ 来源卡和分叉武器探针，避免研究页发展出第二套地图真相；
- 视觉上使用路线图/训练场语法，重点突出路线和攻击暴露，不模拟或复制任何 CS1.6 贴图、几何或插件。

## 放弃的方案

### 只维护 Markdown 和无渲染测试

保留成本低，但无法观察画布上的分叉、终点和攻击点是否同时可见；不满足真实画布验证目标。

### 直接把研究页挂到生产主页

会把尚未经过真机、多人和真人验证的研究结论误当作产品功能，也违反研究/生产边界。

### 在研究页内实现一套新的跳跃物理

会制造第二个权威来源，并让画布的视觉可读性被未验证物理掩盖；本页只观察路线合同，物理仍由独立灰盒承担。

## 后果

- KZ 研究现在拥有“规则 → 灰盒 → 真实画布 → 真人/多人”连续证据链中的前三层；
- 画布本身不证明玩家 3 分钟理解、不证明真实镜头、不证明 2–4 人拥挤公平，也不证明最终资产可以发布；
- 后续真人测试必须记录段落识别、路线选择、攻击归因和复活重入，而不能只记录是否到达终点；
- 若画布发现路线关系不可读，应先修改研究路线合同或相机合同，不直接修改生产地图。
