# ADR-045：Arena V2 武器上下文概览契约

## 状态

Accepted for V2 presentation prototype（V2 表现原型已接入；权威层最终武器迁移待单独批次）

## 背景

第一版武器卡只展示一组主动作数值，能够区分重锤、锁链和冲锋盾，但不能表达热血英豪武器在地面、跑动或空中状态下改变用途的关键规律。若只依靠外观和一句定位，玩家无法知道为什么同一把武器在不同地图和移动状态下值得重复练习。

## 决策

武器公开概览采用三层信息：

1. 主动作 8 项真实数值：有效距离、出招速度、收招时间、横向击飞、纵向控制、硬直时间、自身位移风险、再次使用时间；
2. 至少两个动作上下文：当前首批为 `ground` 和 `aerial`，各自提供距离、前摇、横向作用和垂直作用；
3. 可读战斗语义：核心动词、主要代价和基础反制。

在三层之外，概览合同还强制要求两条不可省略的语义：命中结果和地图用途。前者说明命中改变的是击退、距离、落点还是路线；后者说明这把武器在哪类空间中值得使用。它们作为 `hitResultMessageId` 和 `mapUseMessageId` 进入 Product 表现定义，不由 UI 临时拼文案。因为这是必填字段，`ProductContentPresentationDefinition` 内层 schema 已升级为 2，避免旧概览被静默当作完整 V2 数据。

所有数值由当前权威动作调优投影到 Product 表现定义，不能在 UI 里重新手写一套平衡数字。`higher-is-risk` 与普通的“越高越好”分开，避免把冲锋距离误读为纯收益。

## 取舍

- 不在第一屏展示完整招式树、资源系统或复杂连招；
- 不因为参考对象有更多动作，就给 Arena 增加更多操作按键；
- 不把当前 V1 `EquipmentDefinition` 直接改成最终 V2 武器合同；
- 不把地面/空中上下文做成两把独立武器，收藏仍按一个武器 ID 计算。

## 当前证据

- `ProductContentPresentationDefinition.overview` 已支持核心动词、代价、反制、命中结果、地图用途和上下文数值；
- 主页已显示 3 把当前武器的主动作数值、地面/空中快速差异和横向公开数值比较矩阵；
- `ProductUiSceneModel.weaponComparison` 要求当前武器使用同一组可比较字段，网页 DOM 测试已验证不同武器的实际数值同屏出现，并保留 `higher-is-risk` 的风险方向；
- Web DOM 与 Canvas 两条局外表现路径都消费同一比较模型，避免小游戏平台只显示外观而缺少公开数值；
- 重锤、锁链、冲锋盾的数值均从 `ARENA_GAMEPLAY_V2_TUNING.attacks` 读取；
- 重点内容测试验证了重锤空中距离和冲锋盾自身位移风险语义；
- 浏览器验收已验证 3 张武器卡、风险标识和角色选择交互。
- 当前规则/物理原型进一步验证了冲锋盾自身冲量、三把武器空中命中节奏，以及重锤/锁链/冲锋盾三组双人同时出招的先后结果；详见[武器攻击者失位与双人争夺原型结果](../research/arena-v2-weapon-contest-prototype-results-v1.md)。

## 后续门禁

进入 V2 权威层迁移前，必须补齐：

- 无渲染 1v1 对比实验；
- 生存模式临时等级对上下文数值的改变规则；
- 命中/击飞/挥空反馈与公开字段的一致性测试；
- 真人测试中的武器识别率、数值差异解释正确率和首次失败后的复玩率；
- 真实多人拥挤和攻击/跳跃互相穿插时的命中顺序与可读性；
- 若删除 V1 格挡，重新建立 Replay、规则签名和发布证据基线。
