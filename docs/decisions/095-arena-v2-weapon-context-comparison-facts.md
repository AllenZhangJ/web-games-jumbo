# ADR-095：武器概览补充地面/空中场景差异事实

## 状态

已接受（2026-07-28）

## 背景

热血英豪式武器学习不是只比较一组攻击数字。同一件武器在地面、空中、边缘和不同路线中的有效距离、覆盖、前摇、击飞与风险会改变；Arena 已经把地面/空中数值放入完整比较矩阵，但玩家首读武器卡仍需要自己翻到矩阵中寻找场景差异。

## 决策

在 `ProductUiSceneModel` 的武器卡上增加 `contextComparisonFacts`，直接从已生成的地面/空中横向比较行派生：

1. 只使用同源 `weaponContextComparison`，不新增战斗字段或手工文案数值；
2. 只有唯一极值才能成为“地面/空中某项最远、最宽、最快或最弱”等事实，并列极值继续阻塞；
3. 每张卡最多两条，优先保留一条优势与一条代价；排序优先空中上下文，再按公共数值轴优先级；
4. 事实保留上下文 ID、上下文标签、数值轴 ID、原始值、单位、精度和方向类别；
5. Web Product 武器卡显示场景事实，完整地面/空中矩阵继续保留；Canvas 不另建事实来源，仍绘制同源比较表；
6. 不计算“地面/空中综合战力”，不排序武器，不改变 MatchCore、武器调优或研究候选迁移边界。

## 备选方案

### 继续只显示完整场景矩阵

- 优点：不增加卡片字段。
- 拒绝原因：玩家要先扫描 16 行场景数据，无法在选择武器时快速理解“它在哪个空间更突出”。

### 把地面和空中数值合成一个场景评分

- 优点：可以用一个数字展示差异。
- 拒绝原因：会掩盖热血英豪式的空间取舍，把不同动作上下文错误相加。

### 手工填写每把武器的场景标签

- 优点：文案可自由组织。
- 拒绝原因：调优或上下文定义变化后容易漂移，破坏概览与权威 Definition 的同源关系。

## 后果

- 武器首屏同时表达公共数值差异和地面/空中使用空间；
- 完整矩阵仍是精确核对面，场景事实只是阅读入口；
- 并列和缺失数据不会被包装成武断结论；
- 多语言仍需把事实词汇迁移到消息目录；
- 真机字号、真人读数正确率和长期留存仍未被自动化测试证明。
