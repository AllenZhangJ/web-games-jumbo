# ADR-046：武器概览先显示数值比较

## 状态

Accepted for current product UI（不扩展 V2 页面导航，不改变权威规则）

## 日期

2026-07-27

## 背景

Arena 的主要深度来自武器和地图，而不是角色数量。当前主页已经有武器卡和公开数值比较矩阵，但原来的视觉顺序是先看卡片文案，再滚动到数值矩阵。在窄屏上，玩家可能先记住外观或一句定位，却没有看到重锤、引力锁链和冲锋盾在距离、风险等字段上的实际差异。

如果把“数值区别”留在详情页或只用进度条表达，就无法满足玩家在武器概览中快速决定“这把武器与另一把有什么不同”的要求。

## 决策

武器概览采用“比较矩阵 → 武器语义卡”的固定顺序：

1. 第一层显示同一组公开数值的横向比较，保留单位、实际数值和方向语义（↑优势、↓更省反应、⚠风险）；
2. 第二层显示核心动词、命中结果、地图用途、主要代价、反制和地面/空中上下文，解释数值意味着什么；
3. 数值仍由 `ProductUiSceneModel.weaponComparison` 统一投影，Web DOM 与 Canvas 不各自维护一套数据；
4. 窄屏允许比较矩阵横向滚动，但不增加新的页面、武器详情系统或复杂筛选。

## 未采用的方案

### 保持卡片优先

- 优点：阅读语义更像传统卡片；
- 放弃原因：数值是本项目武器区别的关键证据，卡片优先会把核心差异推到滚动之后。

### 增加独立武器详情页

- 优点：可以容纳更多招式和背景；
- 放弃原因：当前问题是概览可读性，不是信息容量不足；增加页面会提高首次理解成本。

### 只使用进度条，不显示数字

- 优点：视觉轻量；
- 放弃原因：没有单位和实际数值，玩家无法可靠比较距离、时间和自身风险。

## 影响

- 玩家可以先看到武器之间的数值差异，再用卡片理解适用场景；
- 当前生产 V1 只改变主页展示顺序和边界样式，不接入 V2 模式、地图收藏或生存进度；
- 真实设备上的字号、横向滚动和玩家正确解释率仍需单独验收；
- 若未来新增武器，必须继续提供同一组可比较字段，不能退回“只有外观和一句定位”。

## 当前证据

- `index.html` 已将公开数值比较矩阵放到武器卡列表之前；
- Web DOM 测试已覆盖三把武器同屏比较，验证有效距离差异和冲锋盾自身位移风险方向；
- [ADR-045：武器上下文概览契约](045-arena-v2-weapon-context-overview.md) 继续约束数值来源、上下文和语义字段。
