# ADR-076：多目标遮挡先固化观察证据，不扩张双人权威边界

- 状态：accepted
- 日期：2026-07-28
- 范围：Arena V2 武器 targeting、视线遮挡研究、命中反馈与当前 MatchCore 参与者边界

## 背景

武器研究已经证明，武器差异不能只停留在伤害或攻击距离，还必须让玩家理解“攻击线里谁先被命中、谁被近目标遮挡、为什么反馈没有落到远目标”。如果直接把研究中的多个目标注册为生产参与者，就会把观察问题、多人规则、网络同步和权威命中顺序混成一次迁移，超出当前 1v1 产品边界。

## 决策

1. 当前生产 MatchCore 继续保持双人参与者边界；多目标遮挡不改变参与者数量、回放 schema、网络协议或默认生产模式。
2. 使用内容层候选地面 `ActionDefinition` 的真实 targeting 参数，建立独立、确定性的研究探针，验证单目标、同线近目标遮挡远目标和侧向进入三类观察场景。
3. 研究探针可以输出候选目标、深度、遮挡关系、可见目标负担和反馈歧义，但不替代 `ActionResolver`，不写入权威 MatchCore 状态，也不伪装成三人或网络多人命中规则。
4. 未来若进入多人生产设计，正式反馈事件必须携带足以区分目标身份或近/远深度的权威语义；表现层只能消费该事件，不能根据画面重新判断遮挡或命中对象。
5. 侧向进入属于真实双人 Replay 的移动与朝向证据；它与多目标遮挡探针分开验收，不能用其中一项替代另一项。

## 被拒绝的替代方案

### 直接把研究目标扩成三人 MatchCore

拒绝原因：会同时扩大权威状态、回放、命中顺序、网络同步和测试范围，且当前用户目标仍是简单入门、少角色和以武器/地图学习为核心，不应在观察问题尚未验证前扩张生产维度。

### 用最终画面推断命中目标

拒绝原因：画面层无法可靠区分近目标命中、远目标被遮挡和远目标离开攻击线；这会破坏命中反馈的因果合同和 Replay 一致性。

### 只增加一个通用命中特效

拒绝原因：同线多目标场景中玩家仍不知道目标身份与深度，无法形成稳定的武器学习记忆；正式目标身份语义必须来自权威事件。

## 后果

- 现在可以用真实候选 Definition 验证多目标观察负担，同时保持 Arena 生产系统稳定在 1v1；
- 侧向进入、近目标优先和远目标遮挡拥有可复验的研究证据，但不再被误写成三人/网络多人已完成；
- 后续若要做多人，需要另立参与者模型、命中顺序、网络同步、反馈身份和真人可读性门禁；
- 当前仍需完成最终声音/特效资产、设备可读性和真人反馈测试，研究探针不能关闭生产迁移门禁。
