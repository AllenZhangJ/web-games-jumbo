# ADR-104：KZ 竞速先以本地 2–4 人流程合同验证

## Status

Accepted（研究工具链）

## Date

2026-07-28

## Context

Arena 的竞速模式已经确定为 2–4 名玩家在 KZ 风格跳跃地图上争先到达终点；地图板块不掉落，被攻击击落后 3 秒原处重生。此前已经有单人路线、分叉路线、多人拥挤和局部复活探针，但还没有把倒计时、路线输入、终点胜负、攻击和复活放进同一条可重复流程。

缺少这个流程时，“2–4 人竞速”仍然只是产品文档中的规则描述；直接进入网络实现又会把本地状态机、同步和真人理解问题同时引入，难以判断失败来源。

## Decision

新增 `runArenaV2KzRaceMultiplayerPrototype()` 作为研究工具链的本地竞速合同：

1. 复用 `ArenaV2JumpRoutePrototype` 的六段路线、`MovementSystem`、`ArenaRuleEngine` 和轻量 `PhysicsWorld`；
2. 覆盖 2、3、4 名参与者，先经过 60 tick 倒计时，再进入 running；
3. 以 `surface-06-wire + finishAnchor` 判定到达终点，第一名写入 winner，其余参与者继续作为研究观察记录；
4. 攻击场景使用现有冲锋盾 Definition，在当前路线状态满足窄路/走钢丝接近条件时尝试攻击；不人为注入命中或掉落；
5. 角色掉落后进入 respawning，等待 180 tick，在该角色最近一次安全支撑位置恢复；用位置误差和支撑面 ID 检查“原处安全快照重生”；
6. 终点产生后仍允许最多 210 tick 的研究观察，以便记录已经发生的 3 秒重生；这段观察不是生产比赛继续时间，也不改变 winner。

原型保持 `productionStatus: research-only`，不进入网络层、默认 MatchMode 或生产 MapRegistry。

## Alternatives Considered

### 只复用单人路线完成结果

- 优点：已有结果稳定，成本低。
- 拒绝：无法验证多人碰撞、终点顺序和竞速状态变化。

### 先做网络竞速

- 优点：更接近最终上线形态。
- 拒绝：同步、延迟、断线和本地规则会同时变化，不能先固定单机权威语义。

### 为了保证测试通过直接注入击落/命中

- 优点：可以稳定展示重生。
- 拒绝：会绕过 Rule/Targeting/Physics，无法证明武器和地图真的能产生竞速后果。

## Consequences

- 2–4 人无攻击流程已经可以在同一条路线中完成倒计时、到达终点和确定性胜负记录。
- 攻击场景保留真实差异：2 人场景本轮尝试未命中，3 人场景出现命中→掉落→180 tick→原安全位置重生，4 人场景出现同一动作多目标命中但未形成掉落。
- 这证明的是本地规则链和流程合同，不证明网络同步、真人公平性、镜头可读性或最终竞速平衡。
