# Arena V2 局外信息原型结果 V1

## 文档状态

- 状态：已完成无渲染页面合同、关键流程验证、局外下一目标合同、武器概览真实 DOM 接入、独立 11 页面研究页、统一布局草图、下一目标可切换研究面和触控/窄屏规格审计；其余生产页面接入、真实字号密度、真机触控和真人阅读率仍待验证
- 日期：2026-07-27
- 目的：把“11 个页面”收敛为信息职责和点击预算，而不是提前实现 11 套复杂系统
- 不代表：V2 页面已经接入当前生产 V1 导航

## 1. 原型入口

入口为 `runArenaV2UiInformationPrototype()`，位于 `packages/arena-v1-experiment`。它只验证页面职责、必需信息和流程，不依赖 DOM、Renderer、墙钟或生产 Product 状态。

页面合同固定保留 11 个信息入口：

```text
加载 → 首页 → 模式选择 → 角色选择 → 竞技准备（1v1 / 竞速）
                                      └→ 生存准备
首页 → 武器索引 → 武器详情
首页 → 地图索引 → 地图详情
对局结束 → 结算/奖励
```

这些入口按四个信息层组织：进入、选择、收集、反馈。对局本身是战斗状态，不计入局外信息页面。加载页是无点击的入口状态；1v1 和竞速共用 `match-prep` 模板，不再单独计 `race-prep`。

## 2. 关键流程结果

| 流程 | 页面序列 | 操作数 | 结果 |
|---|---|---:|---|
| 首次进入 | 首页 → 模式选择 → 角色选择 → 1v1 准备 | 3 | 通过 |
| 学习武器 | 首页 → 武器索引 → 武器详情 → 1v1 准备 | 3 | 通过 |
| 学习地图 | 首页 → 地图索引 → 地图详情 → 竞技准备（竞速变体） | 3 | 通过 |
| 生存重开 | 结算/奖励 → 生存准备 | 2 | 通过 |

验证结果：

- 11 个页面 ID 唯一；
- 每个页面都有明确的玩家问题和下一步主动作；
- 武器详情强制包含动作时序、命中结果、适用地图空间和反制方式；
- 生存准备强制包含开局无武器、每 20 秒刷新 3 把实体武器、靠近自动拾取或替换、未拾取 10 秒消失和两次掉落规则；
- 结算页在 1 次点击内支持再来一局，2 次点击内支持切换目标；
- 原型没有引入商城、复杂养成、多货币或其他复杂系统。
- 交互审计固定 11 个页面导航按钮、4 个流程按钮、48px 最小触控目标和 760px 窄屏断点；每个页面必须有非空主动作。

## 3. 研究转设计的结论

### 3.0 首屏只回答当前问题

本轮为 11 个页面合同补充 `firstViewInformation` 与 `deferredInformation`。首屏最多保留 3 项必须信息，详情或次屏再呈现个人记录、地图适配和推荐时长等内容；这不是减少信息，而是把“现在要做什么”和“之后可以研究什么”分开。原型会拒绝首屏字段不属于页面必要信息的合同，避免页面为了显得丰富而产生第二套内容。

### 3.1 武器页面仍采用两级信息

- 首页/武器索引：只回答“选不选它”，展示核心动词、9 项数值、地面/空中差异和风险；
- 武器详情：回答“怎么练它”，展示动作时序、命中结果、地图条件、反制和个人记录。

这与热血英豪研究中“同一把武器在不同空间上下文中改变价值”的结论一致，也避免把完整招式树塞进第一屏。

### 3.2 地图页面只承担熟悉路线

地图详情需要展示六段路线、难度六维、安全/压力/选择段和武器适配空间，但不增加编辑器、机关树或复杂地图养成。

### 3.3 生存页面只承担重开理由

生存准备、局内供给和结算只围绕四个信息：坚持目标、当前临时武器、复活余量、下一次要尝试什么。奖励和熟练记录可以累积，但不在本原型中引入战斗外数值加成。

### 3.4 局外只给一个下一目标

`resolveArenaV2UiNextGoal()` 将局外进度转换为一个带有目标、理由、进度值和立即行动的卡片，不同时推送任务列表。当前原型按以下顺序收敛：

```text
武器未收齐 → 熟悉武器地面/空中用法 → 熟悉地图段落 → 冲击下一档生存记录
```

这条顺序服务于“武器和地图是主要深度”的定位：收集扩大可尝试的战斗语法，武器上下文练习把数值差异变成操作理解，地图段落练习把命中和位移转化为路线判断，生存记录提供长期重复挑战。原型拒绝自相矛盾的进度数据，且只属于 `arena-v1-experiment` 研究/测试工具链；它不代表当前生产 V1 已拥有 V2 的持久化收集或生存进度。

## 4. 未关闭的问题

- 11 个入口在手机实际尺寸下是否仍然清晰；
- 首屏最多 3 项信息在真实字号和窄屏上是否仍然可扫读；
- 新玩家能否在 10 秒内说出两把武器的数值差异；
- 地图详情是否能帮助玩家在 5 秒内找到第一段路线；
- 生存结算的信息是否真的提高再次开始率；
- 页面原型接入生产 V1 状态机时，是否需要独立 V2 导航边界。
- 目标卡在真实页面和移动尺寸下是否仍然足够醒目，且不会被误解为复杂任务系统。

本文件关闭的是“页面职责和关键点击预算是否可写成合同”，不关闭真实页面验收和留存指标。

## 4.1 单一下一目标研究面

本轮将 `resolveArenaV2UiNextGoal()` 接入独立 `ui-information.html` 研究页，新增四个固定进度阶段：收集、熟悉、地图和生存。研究者可以切换阶段，直接观察目标标题、理由、进度值/目标值和立即行动；每个阶段只显示一个目标，不生成任务列表。

这关闭了“目标合同存在但研究页看不到”的工程缺口，仍不关闭生产结算页接入、持久化进度、真实手机触控和真人留存效果。决策记录见[ADR-094：局外研究页必须把单一下一目标做成可切换验证面](../decisions/094-arena-v2-ui-single-next-goal-study-surface.md)。

## 5. 武器概览的真实页面验证

为了满足“玩家至少能在概览中看出武器数值差异”，当前 V1 主页已经增加一层横向公开数值矩阵，不再只依赖三张独立卡片：

- `ProductUiSceneModel.weaponComparison` 由同一组公开数值定义派生，要求所有当前武器使用同一组可比较字段；
- Web DOM 主页和 Canvas 局外主页都显示数值名称、当前武器列、实际数值和方向语义（↑优势、↓更省反应、⚠风险）；
- DOM 验证覆盖重锤 `1.80 格` 与引力锁链 `5.00 格` 同行差异，以及冲锋盾的风险方向；
- Canvas 绘制验证覆盖数值名称和格式化值；实现入口为 `src/entry/web-product-ui-surface.ts`、`packages/arena-product-presentation/src/product-canvas-painter.ts`，模型入口为 `packages/arena-product-presentation/src/product-ui-scene-model.ts`，测试见 `tests/entry-web-product-ui-surface.test.ts` 和 `packages/arena-product-presentation/test/product-presentation-boundaries.test.ts`。

本轮页面收敛又将主页武器概览调整为“先看数值差异，再看语义卡片”：公开比较矩阵现在排在武器卡列表之前，三把武器的有效距离与冲锋盾自身位移风险在 Web DOM 测试中同屏验证。这个调整只改变当前主页的信息顺序，不新增页面或 V2 持久化状态；决策记录见[ADR-046：武器概览先显示数值比较](../decisions/046-arena-weapon-overview-comparison-first.md)。

这关闭的是“数值是否能在当前主页同屏比较”的工程验证，不等于关闭真机字号、横向滚动和真人能否正确解释数值的研究问题。

## 6. 独立 11 页面研究页

新增 `ui-information.html` 和 `src/entry/ui-information-study.ts` 作为局外信息架构研究页。它直接消费 `runArenaV2UiInformationPrototype()` 的页面合同，不另写一份页面列表，当前可执行验证包括：

- 切换 11 个页面入口，查看页面问题、信息层、首屏项目数、点击预算和主/次动作；
- 切换首次进入、学习武器、学习地图和生存重开四条流程，查看页面顺序和主要操作数；
- 在窄屏 CSS 断点下将页面导航、首屏指标和流程按钮改为单列/双列布局，所有研究操作按钮保留至少 `3rem` 高度；
- 研究合同将最小触控目标具体化为 `48px`，研究页摘要直接显示该门槛；CSS 与无渲染审计使用同一数值，便于后续真机验收；
- 页面加入 `noindex,nofollow`，构建脚本不把它作为生产入口，且不依赖 `MatchCore`、存档或局外真实状态。

这一步关闭的是“11 页合同是否能被研究员和参与者直接浏览，以及后续真机验收使用什么触控门槛”的工程问题，不关闭真实手机触控、字号可读性、真人阅读率和结算后再次开始率。验证入口为 `tests/arena/study/ui-information-study-web.test.ts`，它只检查研究页与生产构建的边界，不把静态 DOM 断言当作真机或真人证据。
