# ADR-084：武器数值可读性任务必须从研究矩阵生成并隔离答案

- 状态：已接受，已接入研究工具链
- 日期：2026-07-28
- 范围：武器概览数值解释任务、参与者题目投影、单次答案评估；不进入默认生产 UI、MatchCore 或玩家存档

## 背景

武器概览已经可以展示主数值、行为数值和地面/空中上下文，但“页面能显示”与“玩家能读懂并用于选武器”不是同一个结论。此前只有真人任务计划，没有能绑定当前数值矩阵的任务合同，容易出现测试题目和实际武器数据漂移，或者把脚本通过误写成真人可读性通过。

## 决策

1. 任务由 `arena-v2-weapon-research-overview-prototype` 的当前矩阵生成，六件逐件研究页另由 `createArenaV2WeaponCaseStudyReadabilityMatrix` 将六件 Definition 投影接入同一合同，并绑定 `sourceMatrixHash`；题目不允许手写另一套武器值。
2. 任务分为四类：直接数值比较、方向语义、地图选择与数值理由、地面/空中上下文差异。它们对应“看懂数值”和“把数值用于玩法”的两层能力。
3. 研究员任务对象保存正确答案、数值证据和所需理由轴；参与者投影只保留题目、选项、上下文和需要回答的数值轴，不能把答案或证据直接泄露给参与者。
4. 若当前矩阵在需要唯一答案的题目上出现并列，任务状态为 `blocked`，整个任务集不能进入真人采集；不得任意加权或制造隐藏小数差异。
5. 单次答案评估只输出逐题选择、上下文和理由轴是否正确，以及该次 `passRate`；它不生成样本量、留存率、解释率或“已验证”结论。
6. 任务合同属于研究/测试工具链，不改变默认生产武器、平衡、Replay、匹配、存档和 UI 入口。
7. 参与者研究页必须在题目前展示同一份研究矩阵的可观察数值；矩阵按地面/空中上下文去重，并在数值名称旁展示单位和方向语义，不能让参与者依赖另一个页面或研究员口头解释。

## 被考虑的替代方案

### 研究员手写五道固定题

- 放弃原因：武器 Definition 或投影变化后，题目答案可能过期；无法证明题目仍然针对当前真实数值。

### 直接在生产页面上读取答案并自动判定真人理解

- 放弃原因：自动化只能证明 DOM 和交互存在，不能替代真人看到信息后的解释；同时会把研究采集状态带入生产页面。

### 只收集自由文本，不保存结构化答案

- 放弃原因：自由文本仍然需要研究员解释，难以稳定判断有效距离、风险方向和地面/空中差异是否被正确理解；结构化选项与理由轴可以先提供可复核的基础指标。

## 后果

正面影响：

- 数值比较题始终绑定当前研究矩阵，能够及时暴露字段漂移或并列答案；
- “答对数值”与“能用数值解释地图选择”被分开记录；
- 参与者侧不会泄露答案，自动化评估不会伪装成人类样本；
- 独立研究页可以直接消费同一份任务合同和同源数值矩阵，并在不进入生产构建的前提下完成结构化回答验证。

限制：

- 当前只有任务生成和单次答案评估，尚无真实参与者、设备字号或触控记录；
- 选项题只能测量预注册的比较轴，不能代替开放式访谈、命中归因和长期留存研究；
- 任务集使用研究候选矩阵，不能据此宣称候选已经进入默认生产。
