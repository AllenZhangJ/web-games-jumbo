# ADR-057：武器战斗语言必须通过地图后果验证

- 状态：已接受，适用于 V2 武器研究与候选评审
- 日期：2026-07-27
- 范围：`packages/arena-v1-experiment` 的武器语言×KZ 地图研究原型

## 背景

Arena 的主要深度来自武器和地图的组合。仅在平面上验证一件武器能否命中，只能证明动作语法成立，不能证明它在断层、迷宫、窄路和走钢丝上会形成可学习的决策。尤其是热血英豪式的击退、前摇和位置关系，如果脱离支撑面和路线分叉，很容易被错误地压缩成“伤害更高”的数值比较。

## 决策

武器战斗语言在进入正式 V2 候选池前，必须通过六段 KZ 灰盒的地图后果探针。最小验证矩阵为：

- 6 段代表空间：平台起点、断层恢复、楼梯攀爬、迷宫、窄路、走钢丝；
- 至少 3 种固定回应：原地承受、侧移、起跳；
- 至少记录前摇、首次命中 tick、横向冲量、是否击落、是否转移到相邻支撑面；
- 固定探针只能作为规则证据，不能替代真人可读性、设备输入和正式平衡验证。

研究原型使用现有 `ArenaRuleEngine`、`MovementSystem` 和 `PhysicsWorld`，不复制地图资产，不在表现层或脚本中直接写入命中、位移、掉落和胜负。

## 被考虑的替代方案

### 只做平面命中测试

- 优点：实现快，结果容易比较；
- 放弃原因：无法发现窄路、边缘和相邻支撑面对击退结果的放大或缓冲。

### 先制作完整地图再验证武器

- 优点：更接近最终体验；
- 放弃原因：成本高且反馈慢，无法在早期排除动作语法与地图后果不匹配的问题。

### 为每种战斗语言制作独立物理规则

- 优点：可以快速模拟特殊效果；
- 放弃原因：会绕过正式 Rule/Core 边界，研究结果无法说明最终实现是否成立。

## 后果

正面影响：

- 武器评审从“动作是否命中”扩展为“命中后是否形成可学习的路线选择”；
- 武器公开数值、地图段落和反制窗口拥有同一套证据；
- 可以在不增加操作按键的前提下，用地图空间制造武器差异。

限制：

- 当前 54 个探针使用固定回应脚本，不能给出真人反应时间；
- 当前封路只有带预警的宽判定动作，没有持续区域状态；
- KZ 灰盒不是最终地图资产，结果不代表正式地图的美术、镜头和网络表现。
