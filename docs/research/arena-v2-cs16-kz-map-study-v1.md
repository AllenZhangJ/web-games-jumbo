# Arena V2：CS1.6 跳跃地图研究初稿

状态：已完成第一轮研究、六类代表地图样本、六段路线合同、分叉路线观察合同、分叉独立灰盒物理可达性原型和研究用 MapDefinition 适配；移动/攻击实战、真机视野和真人路线理解仍待验证（2026-07-28）
用途：为竞速地图基座和生存模式地图复用建立约束，不代表已经完成地图制作。

## 1. 研究对象与项目约束

本项目借鉴 CS1.6 KZ/跳跃地图的路线组织方式，不直接复制第三方地图资源。Arena 竞速模式的最终约束已经确定为：

- 2–4 名玩家同图；
- 方向 + 跳跃即可走完全部路线，不增加新的操作按键；
- 地图板块不掉落，玩家被攻击击落后 3 秒在原处重生；
- 先到终点者获胜；
- 同一张地图还要能去掉终点，复用于生存模式。

因此，借鉴重点不是“把 KZ 技巧原样搬过来”，而是借鉴它把一张地图拆成连续可学习段落、按难度分层、让玩家反复练习同一动作的能力。

## 2. 外部研究结论

KZ 社区通常把地图难度拆成多个等级，并用长跳距离、连续空中修正次数、预加速、连续 Bunny Hop、站立跳等能力描述难度，而不是只用地图长度描述难度。[KZ-Rush 地图难度标准](https://kz-rush.com/en/article/map-difficulty-criterias) 给出了从 Easy 到 Death 的分级示例；CS1.6 KZ 介绍也把 long jump、bunny hop、strafing 和存点练习列为核心学习内容。[CS1.6 KZ 入门指南](https://steamcommunity.com/sharedfiles/filedetails/?id=3272385460)

可转译为本项目的三条规则：

1. 难度必须有来源：距离、节奏、转向、路线识别、受攻击压力分别记录，不能只写“简单/困难”。
2. 地图应该由可命名的段落组成：玩家失败后能说出“窄路段没过”，而不是只知道整张图失败。
3. 段落要形成训练曲线：先单独教一个动作，再把两个动作组合，最后加入对手干扰。

## 3. Arena 地图段落语法

| 段落类型 | 主要学习点 | 竞速表现 | 生存复用方式 |
| --- | --- | --- | --- |
| 基础跳台 | 起跳距离与落点 | 低压热身 | 作为敌人刷新前的移动空间 |
| 断层 | 起跳时机与方向保持 | 失败成本明确 | 作为躲避敌群的断点 |
| 迷宫 | 路线记忆与视野 | 拉开熟练玩家差距 | 作为敌人聚集区与路线选择 |
| 窄路 | 落点精度与减速 | 受攻击风险最高 | 作为高收益但高危险通道 |
| 楼梯 | 连续节奏与镜头适应 | 检验稳定性 | 形成上下层敌人压力 |
| 走钢丝 | 微调方向与跳跃 | 终段高潮 | 作为生存后期的空间压缩 |
| 组合段 | 多个动作连续执行 | 形成完整关卡节奏 | 作为时间段落的难度上升 |

“断层、迷宫、窄路、楼梯、走钢丝”是空间语言，不应改变玩家已有操作语法。首批原型建议每张图只引入 2–3 种段落，再通过顺序、长度和干扰强度形成差异。

## 4. 竞速地图结构草案

一张地图的最小数据结构应包含：

- `mapId`：稳定地图 ID；
- `segments`：有序段落，每段有类型、推荐难度、入口和出口；
- `spawnAnchors`：玩家起点与被击落后的原处重生锚点；
- `finishAnchor`：终点，只在竞速模式生效；
- `hazardProfile`：是否允许敌人或玩家攻击造成掉落；
- `cameraProfile`：大地图移动时的视野边界与镜头跟随；
- `survivalProfile`：去掉终点后，敌人刷新区域和可循环区域。

竞速模式只需要读取 `segments + finishAnchor`；生存模式读取同一套 `segments + spawnAnchors + survivalProfile`，不再增加另一套地图资产。

## 5. 难度与时长目标

首批不建立复杂的 KZ 技巧等级，也不把玩家挡在高级操作之外。先采用四档可理解的地图档案：

| 档位 | 玩家感受 | 推荐完成时长 | 首批用途 |
| --- | --- | ---: | --- |
| 入门 | 每段只要求方向 + 跳跃 | 60–90 秒 | 新玩家第一张图 |
| 熟练 | 需要连续 2–3 个段落 | 90–150 秒 | 常规匹配 |
| 挑战 | 窄路、迷宫和组合段增加 | 150–240 秒 | 熟悉武器后的地图目标 |
| 极限 | 路线长、容错低、攻击窗口多 | 240 秒以上 | 重度玩家收集与排行 |

这里的时长是地图设计目标，不是强制倒计时。玩家基础操作应在 3 分钟内明确，地图熟练度和路线稳定性成为长期提升来源。

## 6. 生存模式的复用边界

生存模式使用竞速地图的空间资产，但不是竞速：

- 不设置终点和先后到达目标；
- 玩家目标是坚持更久；
- 地图不掉落，玩家和敌人可以被击落；
- 第一次被击落后复活，第二次结束；
- 敌人数量随时间增加；
- 每 20 秒提供 3 把武器选择，武器轮次越晚，候选强度越高；
- 地图段落只承担躲避、分流和风险选择，不新增机关系统。

生存地图设计的核心不是“跑完全图”，而是让玩家在同一空间里不断做：靠近武器、绕开敌群、利用窄路制造击落、在安全段重新整理位置。

## 7. 首批原型与验证

首批只做一张 6 段地图：基础跳台 → 断层 → 楼梯 → 迷宫 → 窄路 → 走钢丝。需要验证：

1. 新玩家是否能在 3 分钟内理解方向 + 跳跃；
2. 竞速失败后是否能在 3 秒重生并立即继续；
3. 同一地图在 1v1 和 2–4 人时是否仍能看清路线；
4. 去掉终点后，生存模式是否能产生躲避路线，而不是变成原地站桩；
5. 攻击是否会改变路线选择，而不是只决定谁先按键。

## 第二轮：把地图段落变成可测量的路线合同

第一轮的“断层、迷宫、窄路、楼梯、走钢丝”还只是空间词。结合 KZ 社区按跳跃距离、空中修正、预加速和连续节奏划分难度的做法，[KZ 地图系统说明](https://docs.cs2kz.org/systems/maps) 以及地图审核对路线可读性和完成条件的要求，[KZ 地图审核说明](https://docs.cs2kz.org/mapping/approval)，Arena 的每个段落需要进一步写成六维档案：

| 维度 | 记录内容 | 玩家感受 |
| --- | --- | --- |
| 距离 | 起点到落点的水平/垂直比例 | 能不能跳到 |
| 节奏 | 连续起跳间隔与落地窗口 | 能不能连续走 |
| 转向 | 需要几次方向修正、是否空中修正 | 能不能控制 |
| 路线识别 | 分叉数量、错误路线的代价 | 能不能看懂 |
| 恢复成本 | 失败后退回多少、3 秒重生后的安全度 | 愿不愿再试 |
| 战斗暴露 | 窄路、边缘和敌人可攻击窗口 | 武器是否改变路线 |

### 2.1 段落合同

首批地图段落统一使用以下最小字段，后续可以直接映射到 Map Definition：

```text
segmentId
kind: basic-platform | gap | stairs | maze | narrow-path | wire | composite
lesson: 本段只教一个主要动作
remix: 将上一段动作组合一次
difficulty: distance / rhythm / turn / route / recovery / combat
entryAnchor
exitAnchor
respawnAnchor
survivalLoopRole: safe | pressure | choice | recovery
```

每段必须先有一个“教动作”的版本，再有一个“组合动作”的版本；不能一开始用连续高难跳跃制造失败。这样才能满足“3 分钟掌握基础操作”，同时把长期时长放到路线熟练和武器选择上。

### 2.2 六段灰盒的真实验证顺序

首批六段地图不再只验证“能不能走完”，而按以下顺序验证：

1. **基础跳台**：第一次失败后，玩家能否说出是跳早、跳晚还是方向错误；
2. **断层**：玩家是否只需方向 + 跳跃，不依赖新增动作；
3. **楼梯**：连续节奏是否比单个长跳更难，但不产生镜头迷失；
4. **迷宫**：错误路线是否能在 5 秒内被看懂并回到主线；
5. **窄路**：武器命中是否会改变玩家路线选择，而不是让窄路只变成随机淘汰；
6. **走钢丝**：终段是否提供熟练玩家的稳定优势，同时保留可读的失败原因。

### 2.3 竞速与生存的同图复用判定

一段地图只有同时满足以下条件，才允许进入“竞速 + 生存”共用池：

- 竞速中有明确入口、出口和完成方向；
- 生存中去掉终点后，至少存在一条可绕行路线和一处恢复空间；
- 敌人增加时不会把所有玩家逼到同一个站桩点；
- 玩家被击落后，原处重生不会立即被迫重复同一不可避免跳跃；
- 武器的远程、近战和自身位移差异会产生不同路线选择。

研究状态更新：地图部分已从“段落分类”进入“段落合同、研究 MapDefinition、灰盒可达性与验证顺序”阶段；尚未完成的是生产地图资产、带攻击完整场景和真机视野测试，外部 KZ 地图仍不作为生产资产。

## 8. 六段路线合同原型验证

已在 `packages/arena-v1-experiment` 建立 `createArenaV2JumpRoutePrototype()`，它是研究和灰盒验收用的只读路线合同，不是生产地图资产。原型固定为：

```text
基础跳台 → 断层 → 楼梯 → 迷宫 → 窄路 → 走钢丝
```

原型测试验证了：

- 只使用 `direction + jump` 两个基础输入；
- 地图板块不可塌陷；
- 被击落后 3 秒复位；
- 迷宫与走钢丝承担路线选择；
- 基础跳台与断层提供可恢复空间；
- 每段都具备距离、节奏、转向、路线、恢复和战斗六维 1–4 档难度记录。

验证命令：

```text
npx vitest run packages/arena-v1-experiment/test/arena-v2-jump-route-prototype.test.ts --reporter=dot
Test File 1 passed；Test 1 passed
```

这次验证关闭的是“首批路线是否能写成可执行合同”，真实跳跃距离的轻量物理验证见下一节；它仍没有关闭新手 3 分钟理解、熟练玩家完成时长、窄路攻击暴露和生存绕行空间。

## 9. 六段路线轻量物理灰盒结果

已在同一实验包中增加 `runArenaV2JumpRoutePrototype()`。它不启动 Renderer，也不把路线写入生产 `MapDefinition`，而是把六段合同映射为明确的矩形 surface，接入当前轻量物理世界和 `MovementSystem`，用固定方向 + 跳跃输入策略运行。

验证命令：

```text

Test File 1 passed；Tests 2 passed
```

固定 seed/输入下的结果：

| 指标 | 结果 |
| --- | ---: |
| 路线 ID | `arena-v2-kz-base-route-prototype-v1` |
| 完成状态 | 通过 |
| 完成段落 | 6/6 |
| 总耗时 | 310 tick，约 5.17 秒的实验时间 |

## 9.1 第三轮：把 KZ 难度转换成回应合同

KZ-Rush 的难度标准把距离、空中修正和连续节奏拆开记录，而不是把整张图压成一个等级。[KZ-Rush 地图难度标准](https://kz-rush.com/en/article/map-difficulty-criterias)；KZ 入门资料也把起点、终点、计时和反复练习作为地图的基本循环。[Kreedz 基础入门](https://kz-rush.ru/en/page/kreedz-basics-part1) Arena 首批地图因此新增三项段落合同字段：

- `responseOptions`：玩家在受到攻击或路线压力时应能尝试的已有回应，只能是保持、侧移或跳跃；
- `responseWindowTicks`：用于固定探针和后续真人任务的最小回应窗口，不代表最终输入延迟或发布平衡；
- `hitRecovery`：命中后是留在本段、转移到相邻段，还是回到本段复活锚点。

六段灰盒当前的回应合同如下：

| 段落 | 可尝试回应 | 探针窗口 | 命中后恢复 |
| --- | --- | ---: | --- |
| 基础跳台 | 保持 / 侧移 / 跳跃 | 10 tick | 本段继续 |
| 断层 | 跳跃 | 8 tick | 回到复活锚点 |
| 楼梯 | 侧移 / 跳跃 | 10 tick | 转移到相邻段 |
| 迷宫 | 侧移 / 跳跃 | 12 tick | 转移到相邻段 |
| 窄路 | 跳跃 | 6 tick | 转移到相邻段 |
| 走钢丝 | 侧移 | 4 tick | 回到复活锚点 |

这不是在给玩家增加操作，而是在地图设计阶段明确“这段允许玩家用什么已有操作争取生存”。如果一段既没有可尝试回应，也没有合理恢复关系，就不能进入竞速和生存共用池。

## 10. 对生存复用的直接结论

六段表面现在具备可被生存模式读取的稳定空间合同：表面不塌陷、存在恢复段、存在选择段，并能按段落记录玩家进入位置。下一步生存模式可以只新增敌人刷新和武器供给，不复制第二套地图几何。

## 11. 武器与 KZ 窄路的交叉验证

为了验证“战斗暴露”不是纸面维度，新增了[武器地图边缘原型结果](arena-v2-weapon-map-prototype-results-v1.md)。实验把当前规则层的横向冲量送入轻量物理，并直接复用了本文件六段灰盒中的 `surface-05-narrow`。

第一轮结果为：重锤和引力锁链在窄路上会把目标送出路线，冲锋盾在同样条件下不会直接击落；同样的三把武器放到宽平台上都不出界。这说明地图宽度和边缘距离会放大武器差异，支持“地图是第二个深度来源”的方向。

这仍然不是完整地图战斗验证：目标本轮不移动，只测试一次地面命中；下一轮必须加入移动目标、攻击者失位、多人拥挤和复活位置。

## 12. 六段路线的攻击段落探针

新增 `arena-v2-kz-route-combat-prototype.ts`，把本文件六段路线的全部表面放进同一个轻量物理世界，然后让同一个攻击者族在每个段落分别使用重锤、引力锁链和冲锋盾命中玩家。攻击、命中、冲量和掉落仍由 `ArenaRuleEngine` 与 `PhysicsWorld` 处理；原型不直接写入玩家位置，也不复制第三方地图资产。

固定 seed `20260727` 下共 18 个组合，全部能在规则层命中。代表性结果如下：

| 段落 | 武器 | 表面宽度 | 结果 | 命中后支撑表面 |
| --- | --- | ---: | --- | --- |
| 基础跳台 | 重锤 | 5.20 | 击飞出界 | 无 |
| 基础跳台 | 引力锁链 | 5.20 | 命中但安全 | 原表面 |
| 迷宫 | 冲锋盾 | 2.20 | 击飞出界 | 无 |
| 窄路 | 重锤 | 3.60 | 命中但安全 | `surface-06-wire` |

这组结果补上了“地图几何可达”与“地图战斗可用”之间的证据：基础跳台上重锤和锁链已经产生不同后果；迷宫的选择段会放大冲锋盾的直线风险；窄路上的重锤没有直接终局，是因为当前灰盒相邻的走钢丝表面接住了目标。也就是说，恢复空间和相邻表面会改变武器的实际价值，不能只用表面宽度或武器横向冲量单独推断公平性。

前面的 18 个基础组合仍是“静态命中边界”，不是完整路线对战；本轮新增的回应版本只测试固定的短侧移和一次起跳，攻击者也没有追击或失位决策。因此当前关闭的是“六段地图与武器规则可以在同一物理链路下产生可比较后果”，没有关闭“真人是否能读懂路线、是否有足够反应窗口、复活后是否能重新进入路线”。详见[ADR-054：KZ 段落攻击探针复用地图与武器规则](../decisions/054-arena-v2-kz-route-combat-probe-boundary.md)。

### 12.1 玩家回应对照

本轮在同一探针上加入三种响应：`hold`（不回应）、`strafe`（最多 10 tick 的横向移动意图）和 `jump`（tick 0 发起一次正式地面跳跃）。横向移动和跳跃都由 `MovementSystem` 处理，探针不直接改玩家位置。固定输入结果的代表样本如下：

| 段落 | 武器 | 不回应 | 10 tick 侧移 | 起跳 |
| --- | --- | --- | --- | --- |
| 基础跳台 | 重锤 | 击飞出界 | 击飞出界 | 命中但落到楼梯段 |
| 迷宫 | 重锤 | 击飞出界 | 击飞出界 | 击飞出界 |
| 窄路 | 重锤 | 落到走钢丝段 | 击飞出界 | 落到走钢丝段 |

这说明“有跳跃键”不等于每个段落都能用跳跃化解击飞：迷宫段没有足够的相邻恢复空间，跳跃仍然会被送出路线；基础跳台和窄路则因为后续表面存在，命中后还有重新落点的可能。短侧移在本轮三个代表段都没有抵消重锤击飞，窄路还会把玩家带离安全深度，因此不能把“横向移动”当作默认正确答案。

当前结论：KZ 基座需要按段落明确“可回应方式”，而不是只记录难度等级。六段灰盒已经把可用回应、回应窗口、命中后的恢复类型写入 `ArenaV2JumpRouteSegment`；研究 MapDefinition 已经把这套几何、四个竞速起点和六个段落装备锚点接入正式地图合同，但尚未进入生产 Registry。后续仍要用真人视野验证窗口是否可读，并把复活后重新进入的第一个安全锚点作为地图验收项。

### 12.2 复活后重新进入路线的最小探针

为关闭“复活锚点只存在于字段里”的结构性缺口，新增 `runArenaV2KzRouteRespawnReentryPrototype()`。探针选择迷宫段的冲锋盾击落场景：命中仍由 `ArenaRuleEngine` 产生，掉落仍由轻量 `PhysicsWorld` 产生；检测到玩家低于 `killY` 后，先重置 Rule participant，再等待路线合同声明的 3 秒（180 tick），最后把玩家放回 `segment-04-maze` 的 `anchor-stairs-end`。

探针随后再走两个物理 tick，确认玩家实际支撑表面仍是 `surface-03-stair-c`，而不是只比较一组预设坐标。当前结果为：`fallTick` 可重复、`respawnTick - fallTick = 180`、复活表面与重入表面均为 `surface-03-stair-c`，结果为 `reentered-route`。这证明“被击落 → 等待 → 回到声明安全锚点 → 重新获得路线支撑”已经能沿同一 Rule/Physics 链路复现。

该探针仍不等于正式复活体验：没有验证摄像机、无敌表现、多人同时重生、竞速排名冻结或真人是否能立即看懂自己回到了哪一段；这些仍是设备和真人研究项。

## 13. 研究 MapDefinition 适配结果

为关闭“路线合同没有真正落到地图合同”的结构性缺口，新增 `arena-v2-kz-map-definition-prototype.ts`。它只存在于 `arena-v1-experiment` 研究工具链，不注册默认生产地图，负责把六段路线投影为当前权威 `MapDefinition`：

| 项目 | 结果 |

| MapDefinition ID | `research-arena-v2-kz-base-route-v1` |

## 14. 分叉路线与复活重入观察原型

此前 `survivalLoopRole: choice` 只是段落标签，没有真正表达“玩家能在何时看到两条路线、两条路线交换了什么、失败后如何重新识别路线”。本轮在 `ArenaV2JumpRouteSegment` 增加 `branchOptions`，迷宫和走钢丝各声明两条研究分叉，并在 MapDefinition 适配层只保存分叉 ID，不把尚未实测的 `waypoints` 伪装成生产 surface。

`runArenaV2KzRouteChoiceReentryPrototype()` 固定在 tick 120 展示选择、tick 121 记录方向选择；四个场景都等待 180 tick 后回到原段落的复活锚点，并在重入时重新显示同一组分叉词汇。迷宫分为“低位直行 / 高位恢复线”，走钢丝分为“中线稳定 / 边线抢时”，每组分别公开预计路线 tick 和战斗暴露窗口。详细结果见[KZ 分叉路线与复活重入观察原型结果 V1](arena-v2-kz-route-choice-reentry-results-v1.md)。

这一步关闭的是“选择段只有名字、复活只有坐标”的结构缺口，不关闭真实分叉几何、摄像机、攻击、多人生存拥挤和真人是否能在 5 秒内说出选择理由。分叉灰盒验证结果见[KZ 分叉路线独立灰盒结果 V1](arena-v2-kz-branch-greybox-results-v1.md)。

## 15. 分叉独立灰盒物理结果

本轮把四条 `branchOptions` 的研究点转换为独立 surface，并使用真实 `PhysicsWorld + MovementSystem`、整数 tick 和基础 `direction + jump` 输入完成路线。结果不再只引用预设 `routeTicks`：

| 分叉 | 独立 surface | 计划 tick | 实测完成 tick | 结果 |
| --- | ---: | ---: | ---: | --- |
| 低位直行 | 5 | 48 | 76 | 完成 |
| 高位恢复线 | 7 | 68 | 151 | 完成 |
| 中线稳定 | 8 | 56 | 154 | 完成 |
| 边线抢时 | 5 | 44 | 81 | 完成 |

两组分叉都出现了可验证的时间交换：恢复线比直行线慢，宽而绕行的中线比窄而直切的边线慢。这个结果支持“快/安全”作为路线设计方向，但只代表研究控制器和当前灰盒参数，不能直接视为玩家最终速度或生产地图平衡。镜头观察合同已单独记录在[KZ 分叉路线镜头观察结果 V1](arena-v2-kz-branch-camera-observation-results-v1.md)；下一步仍应把同一套灰盒接入武器击落、真实画布和多人拥挤测试。
