# ADR-099：六件逐件武器研究先绑定主战斗语言

## 状态

Accepted

## 日期

2026-07-28

## 背景

六件深研武器已经有逐动作事实、地面/空中研究 Definition、公共数值轴和三步学习路径，但“核心动词”仍是每件案例独立书写的长文本。玩家可以看到很多数值，却不一定能横向理解：一把武器是在封路、换位、压制直线、绕后、读招反制，还是用预判换高回报。

《新热血英豪》官方武器指南与《英豪真经》把武器使用放在距离、错身、跑位、跳位、诱导和地图空间中说明；具体武器页面也分别展示了白金双枪的地面/空中射击、魔血镰刃的延迟危险和幻虎巨拳的蓄力承诺。研究结论因此应先形成可比较的战斗语言，再决定哪些数值轴值得首屏展示。

## 决策

六件逐件研究案例各绑定一个主战斗语言，并由既有 `ArenaV2WeaponFunctionLanguageProfile` 生成统一读出：

| 案例 | 主战斗语言 | 首屏需要关注的轴 |
| --- | --- | --- |
| 魔血镰刃 | 封路 | 覆盖宽度、延迟、预警、再次使用、横向击飞 |
| 真·哈迪斯钩镰 | 换位 | 有效距离、横向击飞、垂直控制、控制时间、收招 |
| 白金双枪 | 直线压制 | 有效距离、覆盖宽度、出手时间、横向击飞、再次使用 |
| 血影钩刃 | 绕后 | 有效距离、出手时间、横向击飞、收招、方向容错 |
| 幻虎巨拳 | 读招反制 | 出手时间、有效窗口、横向击飞、收招、控制时间 |
| 猛犸石斧 | 延迟重击 | 延迟、预警、覆盖宽度、横向击飞、垂直控制 |

绑定必须满足：

1. 每件案例只有一个主语言，避免同一把武器被多个标签稀释；
2. 主语言所需的每个公开轴必须出现在该案例的数值审计中；缺失时构建直接失败；
3. 概览同时显示语言名称、关键数值轴、地图空间和反制方式；
4. 语言绑定是研究推导，不是原作内部设计意图，也不自动创建生产装备、奖励或角色技能。

代码边界为 `arena-v2-weapon-case-study-language.ts` 与 `arena-v2-weapon-case-study-overview-prototype.ts`，研究页只读取这份绑定，不手写第二份武器标签。

## 备选方案

### 继续只展示核心动词

- 优点：改动最少。
- 缺点：每件案例的文字不可横向比较，关键数值轴无法解释为什么重要。
- 不采用：无法支持“武器区别必须在概览中可读”的目标。

### 给每件武器增加多个标签

- 优点：可以覆盖更多动作。
- 缺点：首屏会把主身份变成标签集合，玩家无法判断先学什么。
- 不采用：复杂动作保留在三步学习路径和完整矩阵中，首屏只保留一个主语言。

### 直接把主语言当成正式武器类型

- 优点：可以快速接入生产筛选和收藏。
- 缺点：研究推导会越过真人、地图和反馈门禁，提前冻结生产内容。
- 不采用：继续保持 `research-only`，通过后续 Definition、Replay、地图和真人证据再评估迁移。

## 后果

- 六件武器形成六个可比较的学习入口，数字不再脱离战斗目的。
- 白金双枪补齐“横向击飞”审计轴；如果未来新案例缺少主语言所需轴，会在组合阶段失败，而不是上线后才暴露。
- 概览首屏信息增加一行语言和一行关键轴，窄屏仍保留完整矩阵与折叠学习路径。
- 语言绑定不证明平衡、不证明真人理解率，也不证明 1v1、生存或 KZ 多人场景已完成；这些仍需独立验证。
