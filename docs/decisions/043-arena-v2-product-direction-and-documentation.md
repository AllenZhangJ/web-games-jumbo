# ADR-043：Arena V2 产品方向与文档分层

## 状态

Proposed

## 日期

2026-07-27

## 背景

当前仓库的 V1 文档主要描述本地 1v1 动作竞技场：少量角色、三件装备、单张竞技地图和快速再来一局。近期产品讨论已经形成新的方向：角色控制在六个左右，主要通过武器和地图提供长期内容，同时增加单人生存 1vE，并以约 200 小时的武器收藏和玩法研究作为内容容量目标。

如果直接修改 V1 文档，容易把“已实现基线”“产品方向”“外部研究假设”和“未来计划”混成同一层，导致后续开发误读状态。

## 决策

1. 新版本先建立独立的 `arena-v2-*` 产品、玩法、研究和架构初稿文档。
2. 现有 V1 文档继续作为当前代码与验收基线，不因 V2 方向而改写为已实现内容。
3. V2 文档必须使用“已确认、候选、待研究、暂不引入、已实现”状态标签。
4. 先沉淀产品总纲、玩法框架、武器框架、生存规则、成长目标、界面地图、架构迁移边界和研究清单，再进入大规模代码重构。
5. 热血英豪、CS 1.6 KZ 地图和弹壳特攻队只作为设计研究对象，不能直接复制其资产、名称、数值、地图布局或系统组合。

## 选择理由

- 独立文档可以保留 V1 的工程证据和回滚语义。
- 先写最小规则，可以在代码前发现模式、武器、地图和成长之间的冲突。
- 武器与地图是 V2 的核心内容，应该先建立研究方法，而不是先堆数量。
- 生存 1vE 是独立模式，不应通过伪装成 1v1 参赛者来降低短期开发成本。

## 影响

### 正面影响

- 产品目标、实现状态和研究假设分层清晰。
- 后续搜索结果可以回填到固定研究卡，而不是散落在对话中。
- 架构重构可以围绕模式、武器运行时等级和敌人单位边界进行。

### 代价

- 短期会同时维护 V1 基线和 V2 草案两套文档。
- V2 初稿中的数值和内容数量不能直接进入生产代码。
- 在研究和原型结束前，部分文档会保持候选状态。

## 后续需要新 ADR 或更新的事项

- 是否正式冻结 1v1 + 生存 1vE 为首批模式；
- 生存模式是否采用开局立即供给武器；
- 武器 Definition 与生存 Offer/临时等级的数据合同；
- 生存敌人与 1v1 Bot 的权限边界；
- 跳跃地图的内容许可、原创改造和正式资产来源；
- 最终武器数量、地图数量和 200 小时内容测算。
