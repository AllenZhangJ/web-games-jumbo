- 不代表：V2 页面已经接入当前生产 V1 导航

## 1. 原型入口

入口为 `runArenaV2UiInformationPrototype()`，位于 `packages/arena-v1-experiment`。它只验证页面职责、必需信息和流程，不依赖 DOM、Renderer、墙钟或生产 Product 状态。

页面合同固定保留 11 个信息入口：

```text
首页 → 模式选择 → 角色选择 → 1v1准备
                         ├─ 竞速准备
                         └─ 生存准备
首页 → 武器索引 → 武器详情
首页 → 地图索引 → 地图详情
对局结束 → 结算/奖励
```

这些入口按四个信息层组织：进入、选择、收集、反馈。对局本身是战斗状态，不计入局外信息页面。

## 2. 关键流程结果

| 流程 | 页面序列 | 操作数 | 结果 |
|---|---|---:|---|
| 首次进入 | 首页 → 模式选择 → 角色选择 → 1v1 准备 | 3 | 通过 |
| 学习武器 | 首页 → 武器索引 → 武器详情 → 1v1 准备 | 3 | 通过 |
| 学习地图 | 首页 → 地图索引 → 地图详情 → 竞速准备 | 3 | 通过 |
| 生存重开 | 结算/奖励 → 生存准备 | 2 | 通过 |

验证结果：

- 11 个页面 ID 唯一；
- 每个页面都有明确的玩家问题和下一步主动作；
- 武器详情强制包含动作时序、命中结果、适用地图空间和反制方式；
- 生存准备强制包含开局无武器、20 秒三选一和两次掉落规则；
- 结算页在 1 次点击内支持再来一局，2 次点击内支持切换目标；
- 原型没有引入商城、复杂养成、多货币或其他复杂系统。

## 3. 研究转设计的结论

### 3.1 武器页面仍采用两级信息

- 首页/武器索引：只回答“选不选它”，展示核心动词、8 项数值、地面/空中差异和风险；
- 武器详情：回答“怎么练它”，展示动作时序、命中结果、地图条件、反制和个人记录。

这与热血英豪研究中“同一把武器在不同空间上下文中改变价值”的结论一致，也避免把完整招式树塞进第一屏。

### 3.2 地图页面只承担熟悉路线

地图详情需要展示六段路线、难度六维、安全/压力/选择段和武器适配空间，但不增加编辑器、机关树或复杂地图养成。

### 3.3 生存页面只承担重开理由

生存准备、局内供给和结算只围绕四个信息：坚持目标、当前临时武器、复活余量、下一次要尝试什么。奖励和熟练记录可以累积，但不在本原型中引入战斗外数值加成。

### 3.4 局外只给一个下一目标

`resolveArenaV2UiNextGoal()` 将局外进度转换为一个带有目标、理由、进度值和立即行动的卡片，不同时推送任务列表。当前原型按以下顺序收敛：

```text
武器未收齐 → 熟悉武器地面/空中用法 → 熟悉地图段落 → 冲击下一档生存记录
```

这条顺序服务于“武器和地图是主要深度”的定位：收集扩大可尝试的战斗语法，武器上下文练习把数值差异变成操作理解，地图段落练习把命中和位移转化为路线判断，生存记录提供长期重复挑战。原型拒绝自相矛盾的进度数据，且只属于 `arena-v1-experiment` 研究/测试工具链；它不代表当前生产 V1 已拥有 V2 的持久化收集或生存进度。

## 4. 未关闭的问题

- 11 个入口在手机实际尺寸下是否仍然清晰；
- 新玩家能否在 10 秒内说出两把武器的数值差异；
- 地图详情是否能帮助玩家在 5 秒内找到第一段路线；
- 生存结算的信息是否真的提高再次开始率；
- 页面原型接入生产 V1 状态机时，是否需要独立 V2 导航边界。
- 目标卡在真实页面和移动尺寸下是否仍然足够醒目，且不会被误解为复杂任务系统。

本文件关闭的是“页面职责和关键点击预算是否可写成合同”，不关闭真实页面验收和留存指标。

## 5. 武器概览的真实页面验证

为了满足“玩家至少能在概览中看出武器数值差异”，当前 V1 主页已经增加一层横向公开数值矩阵，不再只依赖三张独立卡片：

- `ProductUiSceneModel.weaponComparison` 由同一组公开数值定义派生，要求所有当前武器使用同一组可比较字段；
- Web DOM 主页和 Canvas 局外主页都显示数值名称、当前武器列、实际数值和方向语义（↑优势、↓更省反应、⚠风险）；
- DOM 验证覆盖重锤 `1.80 格` 与引力锁链 `5.00 格` 同行差异，以及冲锋盾的风险方向；
- Canvas 绘制验证覆盖数值名称和格式化值；实现入口为 `src/entry/web-product-ui-surface.ts`、`packages/arena-product-presentation/src/product-canvas-painter.ts`，模型入口为 `packages/arena-product-presentation/src/product-ui-scene-model.ts`，测试见 `tests/entry-web-product-ui-surface.test.ts` 和 `packages/arena-product-presentation/test/product-presentation-boundaries.test.ts`。

本轮页面收敛又将主页武器概览调整为“先看数值差异，再看语义卡片”：公开比较矩阵现在排在武器卡列表之前，三把武器的有效距离与冲锋盾自身位移风险在 Web DOM 测试中同屏验证。这个调整只改变当前主页的信息顺序，不新增页面或 V2 持久化状态；决策记录见[ADR-046：武器概览先显示数值比较](../decisions/046-arena-weapon-overview-comparison-first.md)。

这关闭的是“数值是否能在当前主页同屏比较”的工程验证，不等于关闭真机字号、横向滚动和真人能否正确解释数值的研究问题。
