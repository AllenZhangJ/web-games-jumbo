# ADR-108：生存供给采用靠近自动替换与 10 秒权威回收

## 状态

已接受并完成 Rule/Core、Bot 与 Presentation read model 实现及主协调独立验收。PA5 总门已冻结，PA6-P 为 `completed / coordinator-approved / formalGate=false`（`95/100`），PA6 runner 正确性已签核；清洁 CPU 环境的正式 ABBA 复验仍未通过，因此 P1 不得 advance。

## 日期

2026-07-28

## 背景

Arena 的基础操作需要在 3 分钟内掌握，深度来自武器、地图和模式，而不是额外交互键。生存 1vE 先前使用“每 20 秒出现 3 把候选”的措辞，部分原型又用脚本字段 `chosenWeaponId` 表达固定取样，容易被误解为暂停战斗并打开三选一界面。

当前正式装备系统还有两个实际缺口：持有主武器的参与者会被自动拾取裁决排除；场上供给没有按生成 tick 自动过期。这意味着现有原型只能证明三实体生成和无武器争夺，不能证明自动替换和场地清理。

## 决策

生存模式采用以下唯一供给语义：

1. 每 20 秒由权威时间轴在三个合法、可达且有预警的位置生成 3 把实体武器。
2. 玩家和敌人通过普通移动靠近并自动拾取，不创建三选一界面、确认框或新的输入字段。
3. 未持有武器时直接占有；已经持有武器时，在同一个权威事务中释放旧武器并占有新武器。
4. 被替换的旧武器直接回收，不重新掉落。
5. 每把供给记录 `spawnTick` 与 `expireTick`；60 Hz 下 `expireTick = spawnTick + 600`。
6. 到达 `expireTick` 时，仍处于 `spawned` 或 `dropped` 状态的供给自动消失；已经被持有的武器不受该供给过期影响。
7. 拾取与过期同 tick 时固定使用“时间轴命令 → 过期裁决 → 拾取裁决”的顺序；到期武器不能在同 tick 被抢救拾取。
8. 同 tick 多人竞争继续使用距离、资格、固定 seed、装备 ID 和参与者 ID 的稳定裁决，不依赖调用顺序或墙钟。
9. 替换、回收和过期必须产生稳定权威事件，并进入 Replay、状态 hash、表现投影和遥测。
10. 玩家要保留当前武器，只需不进入新武器的自动拾取范围；一旦进入范围并赢得裁决，不能弹窗撤销。

## 选择该方案的原因

- 复用普通对战的“靠近即拾取”学习经验，不增加模式专属操作。
- 三把武器作为地图实体，会自然制造路线、风险和争夺，而不是把决策从地图移到菜单。
- 10 秒回收限制场上噪声、实例数量和供给累积，也让玩家需要及时判断是否改变路线。
- 旧武器直接回收可以避免替换后立即反向拾取、无限堆积和敌人围绕废弃武器循环寻路。

## 未采用的方案

### 暂停战斗并三选一

会新增局内界面状态、选择操作和战斗暂停语义，使生存模式偏离地图驱动，也与普通对战的拾取学习不一致。

### 替换时把旧武器掉在地上

会放大场上实例数量，产生反复交换、旧等级武器混杂和敌人寻路噪声，需要额外规则解释哪些掉落继承何种过期时间。

### 用宿主定时器 10 秒后删除

墙钟和前后台状态会破坏确定性、Replay 和跨端一致性，违反权威时间只能使用整数 tick 的约束。

## 影响

- `EquipmentSystem` 需要增加单槽原子替换能力，不能继续无条件排除持有者。
- Equipment Runtime 或模式供给时间轴需要拥有明确的过期身份、回收命令和稳定事件。
- Bot 无武器时与持有武器时都可以评估新供给，但只能输出普通移动输入。
- HUD 需要表现供给位置、最多 10 秒剩余时间、拾取、替换和消失结果；表现层不自行计时或删除实体。
- 历史原型结果继续作为三实体生成和争夺证据，但不能作为替换、回收和生产完成证据。

## 验收条件

- 固定 60 Hz 下，未拾取供给在第 600 tick 前存在，到达第 600 tick 时不可再拾取。
- 持有者进入范围后一次事务完成旧武器回收与新武器占有，不出现空槽中间态或双持状态。
- 1、2、4 个参与者在同 tick 竞争的结果与输入数组顺序无关。
- 相同 Definition、seed 和 InputFrame 得到相同事件、Replay 和最终 hash。
- 前后台、暂停恢复和低表现帧率不改变 600 tick 生命周期。
- 生产和研究文档中不再把该流程描述为三选一界面。
