# ADR-069：命中反馈必须保留失败原因的因果区分

- 状态：accepted
- 日期：2026-07-28
- 范围：Arena V2 武器命中、KZ 地图后果和表现层反馈

## 背景

当前 KZ 原型已经能记录命中、击落、支撑面转移和移动掉落，但如果表现层只显示“失败”或播放同一种音效，玩家无法判断是武器命中、自己路线失误，还是成功避开了攻击线。这样的反馈会直接削弱武器学习和地图熟悉。

## 决策

武器×地图结果必须投影为带因果语义的只读反馈：

- `hit-confirm`：命中成立，目标仍有支撑面，但位置被改变；
- `hit-surface-transfer`：命中改变最终支撑面或路线位置；
- `hit-ring-out`：命中把目标推出安全支撑面；
- `attack-evaded`：目标在有效判定前离开攻击线；
- `movement-fall`：目标在命中前因路线失误失去支撑面。

反馈必须从同一份权威结果快照派生，至少保留命中 tick、最终支撑面、是否掉落、回应类型和武器身份。表现层可以将这些语义映射为特效、声音、文字或镜头，但不能重新判断命中原因。

## 被拒绝的替代方案

### 统一播放“受击”反馈

拒绝原因：会把武器命中与玩家自失误混在一起，无法支持 3 分钟基础学习和地图失败归因。

### 只用最终位置推断原因

拒绝原因：最终掉落位置不能区分“先掉落后被判定”与“命中导致出界”，必须保留命中 tick 和回应结果。

### 在 Canvas/DOM 层重新判断

拒绝原因：会违反 `Rule → Core → Bot → Presentation` 的依赖方向，并可能让声音/特效与回放结果不一致。

## 后果

- 研究原型现在可以验证反馈语义，而不只是验证数值和最终位置；
- 未来命中特效、音效和结算文案可以共享同一反馈 kind；
- 真人测试可以分别询问“为什么掉落”和“是否命中”，得到可比较的归因数据；
- 当前反馈仍是无渲染语义合同，不能宣称设备上的声音、特效和镜头已经验证。
