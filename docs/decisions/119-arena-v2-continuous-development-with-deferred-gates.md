# ADR-119：Arena V2 连续开发与阶段门集中顺延

## 状态

已接受。自 2026-08-10 起取代 ADR-118 中“P2.6 前停止功能扩展、补验前不得继续 P3”的执行顺序限制；所有正式验收标准保持不变。

## 背景

用户进一步明确：其他任务已基本结束，当前 Arena 项目可以开始全部开发；不要等待验证、测试或压测，无法立即执行的门禁顺延，开发优先。同时明确本任务只有当前项目权限，不得与其他项目任务沟通。

P2 已形成 Definition、合同、独立 Mode System、下游组件、具体新局 runtime 与聚合验证基础设施的生产不可达静态候选。继续用中间性能门阻塞后续代码会制造重复冻结和重复性能采样，但直接删除门禁或把未测候选写成通过会降低旗舰目标，二者都不符合授权。

## 决策

### 1. 开发连续推进

- 按 `Rule → Core → Bot → Presentation → Platform` 继续完成 P2.5e、P2.6 真实无渲染绑定，并依计划推进 P3–P6 的生产不可达、版本化、可回滚实现候选。
- 前一阶段缺少测试、构建、压力、设备或真人证据，不再阻塞不存在生产依赖的后续开发；这些状态统一记录为 `verification-deferred / formalGate=false`。
- 新阶段仍须先有明确合同、唯一写者、失败关闭、生命周期、测试代码/失败场景设计、静态多维自检与精确回滚边界。

### 2. 不开放的边界

- 默认 Registry、默认生产 Composition、三端正式入口、正式资产正常加载路径、用户数据迁移、release、merge 和发布状态不会因本决策自动开放。
- 未冻结的平衡数值、敌人数、保护时间、地图时限和经济容量只能留在显式测试/开发 fixture 或待决 Definition，不得伪装成生产默认值。
- 不得把计划、源码存在、静态自检或延期状态写成测试通过、性能通过、设备通过、真人通过、P 阶段 `advance` 或旗舰目标完成。

### 3. 验证集中到下一必要性能聚合点

所有此前登记的定向测试、恶意输入、typecheck、lint、架构检查、Replay/Golden、Coverage、build、PA6、PA7、P2 压力、设备、真人、美术和发布门继续保留。到下一次确实需要性能数据才能决定实现方向或准备生产入口时，绑定届时同一 source identity 统一执行；任一失败仍须修复并使受影响证据重跑。

### 4. 项目与任务隔离

- 只允许读取、修改和协调当前 Arena 仓库与其 Arena 开发/美术任务。
- 不向其他项目任务发送消息，不停止、不复用也不归因其他项目的进程、测试或证据。

## 影响

- 开发吞吐优先，减少中间性能证据被后续源码变化反复作废。
- 缺陷可能在集中验证时跨切片暴露，因此所有候选必须保持版本化、生产不可达和可精确回滚。
- ADR-118 仍保留其“验证不豁免、静态自检、提交与发布边界”约束；仅其停止继续开发的顺序限制被本决策替代。
