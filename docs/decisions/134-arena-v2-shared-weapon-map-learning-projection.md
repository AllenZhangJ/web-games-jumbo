# ADR-134：详情、赛前、局内与结算共用武器×地图学习投影

## 状态

提议：`production-unreachable / code-written-not-run / hardGate=false`。

## 日期

2026-08-13

## 背景

Arena V2把武器与地图学习作为主要长期内容，同一关系当前出现在八个消费位置：

- 武器详情需要把当前竞技模式与地图的具体练习点接到既有地图后果字段；
- 地图详情需要把当前竞技武器的具体练习点接到既有武器后果字段；
- 1v1与竞速开局前需要告诉玩家“这把武器在这张图优先找什么地形”；
- 1v1持有武器期间需要在即时反馈之外保留一个当前地图练习焦点；
- 生存本地拾取或替换武器后需要立即建立武器与当前地图的联系；
- 生存持有武器期间需要在即时提示消失后保留一个短练习焦点；
- 竞速需要在权威下一路段确实符合当前持有武器语法时给出一个短提示；
- 结算需要把本局真实使用过的武器转成一条下一局练习重点。

八个消费位置如果分别读取武器Mode Consequence、地图段落类型和中文消息，会形成多套排序规则；同一把武器可能在详情、准备、局内和结算显示不同地形。仅凭中文名称反查Definition也会形成不可靠的第二身份源。

## 决策

### 1. 建立单一只读投影

`arena-v2-weapon-map-learning-projection-candidate-v1.ts`成为唯一武器×模式×地图机会投影。输入必须显式包含：

- `modeKind`；
- 一把或多把真实武器Definition ID；
- 真实地图Definition ID；
- 焦点策略；
- 未知地图策略。

投影只读取当前20武器/2地图内容目录：武器的模式地形语法来自`modeConsequences`，地图机会来自内容目录拥有的`weaponSituationOpportunityCounts`。按当前地图实际机会数降序、模式地形语法原顺序破同分，最多输出两个地形。内容目录还为每类机会冻结路线序号最早的匹配路段Definition、序号和消息身份；投影同时保留抽象地形摘要，并生成“地形（第N段·路段名）”的具体练习摘要。

投影不读取玩家坐标、支撑面或路线进度，因此具体路段只代表稳定推荐练习点，绝不声称玩家当前位于某段；不写Rule、Match、Reward、Profile或导航。

### 2. 八个消费位置使用受限的合法焦点策略

- 竞技武器详情：当前模式只允许1v1或竞速，且上下文武器必须与详情身份一致；只扩展既有地图后果字段。
- 竞技地图详情：当前模式只允许1v1或竞速，且上下文地图必须与详情身份一致；只扩展既有武器后果字段。
- 竞技准备：必须精确提供当前选择的一把武器，未知武器或地图立即失败关闭；同时校验Definition ID、中文名与地图段落总数一致。
- 1v1持续状态：只使用HUD由权威Frame投影得到的地图Definition、中文名和本地当前持有武器；可见文本只保留第一地形，最多两个具体路段只进入完整无障碍语义。未知地图或显示名漂移立即失败关闭。
- 生存拾取：只在本地真实拾取/替换后使用当前拾取武器和HUD中的权威地图身份；生成、过期和远端拾取不追加学习文案。
- 生存持续状态：只在本地权威持有武器时复用同一投影，可见文本只保留第一地形；最多两个具体路段只进入完整无障碍语义。空手不显示。
- 竞速下一段：只使用竞速Mode Projection已经给出的下一路段Definition、序号和显示名，再与当前持有武器的竞速地形语法闭合；匹配时在既有路线事实追加一个地形，未匹配返回空。它不读取坐标，也不把下一路段写成当前位置。
- 结算回看：只从Product Result V3的真实使用集合中按收藏顺序选择一个稳定复盘焦点；历史结果若使用当前目录外地图，只保留武器使用事实，不猜地图。

### 3. 生存准备保持空手语义

生存准备页只校验地图Definition、中文名和段数，不调用某把预选武器的学习投影，也不显示“本局武器”或武器×地图计划。生存仍默认空手开局，武器学习从局内真实拾取开始。

### 4. 不扩张界面和玩法

竞技准备只在现有页面增加`weapon-map-plan`延后字段。页面数仍为11，每页仍只有一个主动作；不增加训练场、弹窗、任务、奖励、按键、Profile字段、武器数值或地图规则。

武器详情与地图详情只扩展既有`map-consequences / weapon-consequences`延后字段。只有当前模式明确为1v1或竞速时，宿主才显式传入当前武器、地图和模式；未选模式或生存继续显示通用详情，禁止把生存的局外选择误写成开局武器承诺。

## 影响

- 详情、赛前、局内和结算使用同一地形排序，不再维护多套业务规则。
- Definition ID成为输入身份，中文名只作校验和展示，不能反向决定武器或地图。
- 内容目录机会计数变化会统一影响八个消费位置，后续只需审计共享地图级与路段级投影。
- 路线段落调整会由内容目录统一重算最早示例和路段类型匹配，八个消费位置不会各自维护地形到路段的映射。
- 武器详情、地图详情、竞技准备、1v1持续持有、竞速下一段、生存真实拾取/持续持有与结算回看形成同一文案接力，不再各自解释当前武器和地图关系。
- 默认Registry、Composition和生产入口继续关闭；测试、类型检查、构建、浏览器、设备、性能与真人证据全部顺延。

## 未采用的方案

### 各消费位置分别读取内容目录

代码较短，但会产生重复排序、重复本地化和长期漂移。

### 通过中文名反查Definition

本地化文案不是权威身份，改名或多语言会造成错误绑定。

### 生存准备预先推荐当前选择武器

这与默认空手开局、局内随机实体供给和靠近自动替换冲突，会向玩家承诺一把本局未必获得的武器。

### 为学习提示新增训练场或任务页

这违反11页与简单入手边界，也不是建立武器×地图短学习循环所必需。
