# Arena V2 武器最小功能版本合同 V1

## 文档状态

- 状态：已接入开发/测试工具链，仍不是生产武器清单
- 日期：2026-07-27
- 目的：把“学习热血英豪后，保留一把武器最基础的乐趣”从描述性字符串收敛为可检查的结构化合同

## 为什么需要这个合同

12 件参考武器已经有核心动词、命中结果、地图用途、失败成本和不复制项，但如果这些字段只停留在研究卡文本里，评审仍可能退化为“看起来很像一把武器”。本合同要求每个参考案例都能回答：

1. 玩家只用一个基础攻击输入时，武器到底制造什么空间问题；
2. 地面和空中是否仍然是同一套操作下的不同上下文；
3. 命中结果、地图关系、失败成本和反制是否可以被分别说明；
4. 需要玩家理解的公开数值轴是否已经进入概览，尚未闭合的轴是否明确保持阻塞。

这不是把热血英豪的复杂招式搬进 Arena。官方操作指南把移动、跳跃、轻重攻击、瞄准、必杀和拾取物品分开，同时明确拾取武器可以攻击或丢弃；官方武器指南还强调投掷速度、远程瞄准、炸弹延迟和跳跃取消等上下文技巧。[官方操作指南](https://bfo.web.sdo.com/web4/guide/operate.asp)、[官方武器指南](https://bfo.web.sdo.com/web4/guide/wuqi.asp) 说明，武器差异来自同一组基础操作在距离、时机、方向、资源和地形中的结果变化，而不是单纯增加按键。

## 合同结构

每种 Arena 战斗语言声明一份最小版本规格：

| 字段 | 作用 |
|---|---|
| 核心动词 | 玩家一句话能记住的主要行为 |
| 基础输入 | 当前统一为一个 `primary-attack`，不增加新按键 |
| 地面/空中上下文 | 同一输入必须有两个可比较的空间问题 |
| 命中条件 | 距离、方向、区域或落点如何成立 |
| 时机 | 前摇、有效窗口、预警、延迟或取消如何形成责任 |
| 命中结果 | 击退、换位、路线限制或垂直控制如何改变局面 |
| 地图关系 | 哪些平台、边缘、窄路或高低差放大价值 |
| 失败成本 | 挥空、误判、失位或冷却如何给对手反制机会 |
| 反制 | 对手用方向和跳跃能否理解并回应 |
| 不复制项 | 明确删除自动锁定、复杂派生、无敌/格挡叠加等复杂度 |
| 公开数值轴 | 与 ADR-059 的概览、上下文和研究轴合同绑定 |

代码合同：

```text
packages/arena-v1-experiment/src/arena-v2-weapon-minimum-version-contract.ts
```

它把 7 种战斗语言的最小规则投影到 12 件研究卡。每个参考案例仍保留自己的来源、地图用途、失败成本和最小版本文本；结构化规则负责检查“研究卡是否真的能落到一个可评审的 Arena 基础版本”。

## 七种最小版本

| 战斗语言 | 最小版本必须保留 | 首要失败成本 | 当前公开状态 |
|---|---|---|---|
| 冲入 | 一次有限正面位移 + 中等击退 | 冲过头或挥空后失位 | 已就绪 |
| 封路 | 一个可见标记 + 短延迟危险区 | 标记放错位置浪费冷却 | 阻塞：缺延迟/预警正式轴 |
| 换位 | 一次受距离和障碍物限制的拉近/推远 | 方向或距离错误失去主动 | 已就绪 |
| 读招反制 | 可见蓄力、提前回应、到期取消和高回报 | 预测错误暴露空档 | 已就绪 |
| 直线压制 | 一条可读攻击线 + 低至中等击退 | 被贴身或连续空放 | 已就绪 |
| 绕后 | 读取目标朝向的方向性命中 | 正面交换不稳定且路线暴露 | 已就绪 |
| 延迟重击 | 公开预警的指定落点重击 | 目标提前离开后空放 | 阻塞：缺延迟/预警正式轴 |

## 当前验证边界

- 12 件研究卡全部拥有最小版本合同、至少两个上下文、地图用途、反制、失败成本和不复制项；
- 合同仍属于开发/测试工具链，不会自动创建生产 `EquipmentDefinition`；
- `ready` 只说明玩家需要理解的数值轴已经有公开承载，不代表平衡、真人学习或地图公平已经通过；
- 封路和延迟重击继续保持 `blocked`，必须先完成延迟/预警的权威来源、地图后果和真人解释率验证；
- 下一步才是从 7 种语言中选出 6 把首发候选，进入正式武器 Definition、回放和真机体验评审。
