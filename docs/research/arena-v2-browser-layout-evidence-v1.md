# Arena V2 研究页浏览器布局证据 V1

## 文档状态

- 状态：本地浏览器布局检查通过，正式武器概览的数值条已验证；实体手机触控、字体可读性和真人理解率仍未验证
- 日期：2026-07-28
- 范围：武器数值可读性研究页、11 页面局外信息研究页、当前 Product 武器概览
- 运行方式：本地 Vite 开发服务，研究页和 Product 入口均来自当前工作区
- 证据边界：这是 DOM/CSS/响应式布局证据，不是设备验收、真人研究或生产发布证据

## 1. 检查条件

| 页面 | 检查视口 | 关注点 |
|---|---:|---|
| `readability.html` | 1280×720 | 六件逐件研究武器是否同时出现数值矩阵与延迟信号 |
| `readability.html` | 390×844 | 武器卡是否折叠、矩阵是否在容器内滚动、页面是否横向溢出 |
| `ui-information.html` | 390×844 | 11 个入口、4 条流程和 48px 触控门槛 |
| `/` Product | 390×844 | 当前正式武器概览是否仍显示真实比较数据 |

移动视口使用浏览器设备尺寸模拟，不代表真实 iOS/Android/WebView 渲染结果。

## 2. 结果

### 2.1 武器数值可读性研究页

桌面视口下可以看到六件逐件研究武器的概览卡、地面完整数值矩阵和延迟/预警信号；矩阵列明确包含魔血镰刃、真·哈迪斯钩镰、白金双枪、血影钩刃、幻虎巨拳和猛犸石斧。

390×844 下的固定检查结果：

| 指标 | 结果 |
|---|---:|
| 页面级横向溢出 | 无 |
| 六件武器卡 | 6 件，单列显示 |
| 地面/空中矩阵容器 | 343px 宽，表格内容 672px，容器内横向滚动 |
| 延迟/预警信号 | 保留“研究假设 / 未声明”，未把未声明误显示为 0 tick |

这证明窄屏不会把数值列挤出页面，也不会把六件武器差异退化成只有名称和外观；但仍未证明玩家会主动横向滚动并正确解释所有数值。

### 2.2 11 页面局外信息研究页

390×844 下的固定检查结果：

| 指标 | 结果 |
|---|---:|
| 页面入口按钮 | 11 个 |
| 关键流程按钮 | 4 个 |
| 页面入口按钮最小高度 | 67px |
| 流程按钮高度 | 48px |
| 页面级横向溢出 | 无 |
| 页面入口布局 | 单列 |
| 流程布局 | 单列 |

当前研究页的首屏结构在窄屏下可以继续向下阅读，页面职责、首屏信息、延后信息和下一步动作没有被截断。

### 2.3 当前 Product 武器概览

390×844 下，正式 Product 入口仍显示 3 把当前武器和 27 行比较数据，生成 81 个“实际数值 + 方向 + 量级条”单元，比较容器没有产生页面级横向溢出。量级条从同一公开数值的 `value/maxValue` 归一化生成，风险方向保留独立风险色，不生成综合评分。实际展示仍从 Product 内容 Definition 的公开概览投影读取，不调用六件研究案例，也没有把研究候选注册为默认生产武器。

## 3. 结论

本轮关闭了三个工程问题：

1. 六件逐件武器的主数值和延迟信号可以在研究页同屏进入真实 DOM；
2. 11 页面合同在窄屏下仍保持单列职责和可点击入口；
3. Product 武器概览没有因为研究页增加而丢失正式数值比较。

本轮还把“数值区别不能只靠文字表格”落实到正式入口：玩家可以先用量级条发现差距，再用实际数值、单位和方向符号确认含义；这仍然属于同一份权威投影，不是额外的展示数据。

本轮没有关闭四个问题：

- 实体手机上的字号、滚动惯性、触摸取消和 WebView 差异；
- 玩家是否会发现并使用矩阵的横向滚动；
- 10 秒内是否能正确说出两件武器的数值差异；
- 3 分钟基础操作、命中归因、地图失败归因和长期留存是否达标。
