## 2. 7/2/1与注释审阅

六板合计42条采用、12条规避、6条实验。每个格子可见：决策槽位、A0.2.1来源编号、来源短名、为什么采用/规避/实验、对Arena的具体约束、不复制点、许可证徽标及`embedded`/`link-only`状态。SVG另保留`data-entry-id`和`data-decision`供机器复核。

板面底部固定三个可执行结论和两个Anti-reference。武器与战斗反馈已由领域直接视觉证明方向合同，但仍不满足“已有生产视觉样件”的成熟度；`board-ready`不能作为进入P4或VFX Blockout的资产批准。

## 3. 裁切、缩放与移动端证据

- 所有40个嵌入视觉使用`contain`，`sourceRect`覆盖完整批准输入，`croppedPixels=0`；manifest记录显示矩形、审阅人、日期与`approved-no-crop`理由。
- 10%图用于一次查看板面大层级。完整注释明确转交移动端等效长页，避免把`256×144`小字不可读伪装为通过。
- 移动端等效长页逐条放大10个卡片，记录CSS视口、DPR、卡片数量和完整注释状态；它是静态等效评审，不是真机、响应式实现、触控或真人证据。

## 4. 机器门与失败关闭证据

- `generate-arena-reference-boards.ts`消费原A0.2.1 `source-ready`包及`supplemental-source-ready`补充包，生成六板和全部派生证据；除武器、战斗反馈外的四板不得消费补充图。
- `check-arena-reference-boards.ts`复算六板/60来源/42-12-6、44原签核+16补充、武器与反馈各8个领域直接视觉，并核对来源身份、许可、源图与输出哈希/字节/物理分辨率、SVG可见标记、零裁切、10%和移动等效证据；本地路径必须真实存在、位于仓库内且不得经符号链接逃逸。
