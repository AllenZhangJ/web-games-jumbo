# Arena V2：弹壳特攻队参考的局外布局预览结果 V1

状态：11 页面统一布局草图已接入独立研究页，窄屏浏览器验证通过；真实手机、真人阅读率和结算后再次开始率仍待验证（2026-07-28）
用途：把弹壳特攻队研究得到的“目标优先、行为化信息、单一下一步”转成 Arena 11 个局外页面可观察的视觉层级，不复制素材和复杂系统。

## 1. 研究依据

官方 App Store 页面把核心卖点压缩成单手操作、海量敌人、Roguelike 技能组合和多变难度；官方生存指南把武器差异写成自动追击/面对方向，以及开阔空间/首领等使用场景。[官方 App Store 页面](https://apps.apple.com/cn/app/%E5%BC%B9%E5%A3%B3%E7%89%B9%E6%94%BB%E9%98%9F/id1628270358)、[官方生存指南](https://apps.apple.com/cn/ipad/story/id1649510203)

Arena 的最小转译不是复制其具体页面，而是统一四个视觉动作：

```text
当前目标
  ↓
最多三项首屏信息
  ↓
一个主动作
  ↓
开始 / 武器 / 地图 / 记录
```

## 2. 页面实现

`ui-information.html` 继续只消费 `runArenaV2UiInformationPrototype()` 的 11 页面合同。每次切换页面时，研究页同时更新：

- 页面问题和信息层；
- 局外布局草图的标题、首屏信息卡和主动作；
- 首屏/延后信息清单；
- 点击预算和支持模式。

布局草图的卡片不会自行增加内容：卡片数量来自 `firstViewInformation`，最多 3 张；主按钮文案来自 `primaryAction`；延后信息继续在草图下方展示。

## 3. 浏览器证据

本地地址：`http://127.0.0.1:5175/ui-information.html`

### 3.1 桌面交互

- 11 个页面入口均可切换；
- 首页草图显示 3 张首屏卡和“进入模式选择”；
- 武器详情草图显示 3 张首屏卡和“用这把武器开始”；
- 结算/奖励草图显示 3 张首屏卡和“立即再来一局”；
- 四类底部入口固定为开始、武器、地图、记录。

### 3.2 390×844 窄屏

| 指标 | 结果 |
| --- | ---: |
| 页面 client width | 390 |
| 页面 scroll width | 390 |
| 研究页导航按钮 | 11 |
| 武器收藏布局卡片 | 3 |
| 武器收藏主动作 | 查看武器详情 |

窄屏下布局草图的三张卡改为纵向排列，主动作占满可用宽度；没有页面级横向溢出。

## 4. 本页真正证明了什么

1. 11 个页面可以共用同一套视觉骨架，同时保留各自页面合同问题；
2. 首页、武器详情和结算都能在草图中保持一个主动作；
3. 首屏三项信息可以在窄屏中堆叠，而不需要横向滚动；
4. 武器/地图/记录四类长期深度可以被固定在底部入口暗示中，不需要新增复杂基地系统；
5. 页面合同、布局草图和自动化断言使用同一份来源，不会因视觉原型产生第二份页面列表。

## 5. 仍未证明的事项

- 真实手机字体、触控区域和不同安全区下的可读性；
- 新玩家能否在 5 秒内找到主动作；
- 玩家能否在 10 秒内说出两把武器的一个数值差异；
- 结算后单一下一目标是否会提高再次开始率；
- 生产 V1 状态机接入后，11 个入口是否仍能保持同样点击预算。

所以本轮把界面研究从“页面职责合同”推进到“可操作的视觉层级草图”，不把研究页写成生产 UI 已完成。
